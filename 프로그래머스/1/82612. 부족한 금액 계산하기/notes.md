# 부족한 금액 계산하기 (82612)

## 상태
- 제출 완료. `long total = (long)price * count * (count + 1) / 2`, 부족하면 차이, 아니면 0
- 제출 파일: `프로그래머스/1/82612. 부족한 금액 계산하기/부족한 금액 계산하기.cs`

## 내가 한 질문
- 10^9까지 올라가는데 `int`로도 아슬아슬하게 괜찮은가?
- 이용료와 횟수의 등차수열 합을 구한 뒤, 가진 돈과 비교해 차이를 구하면 되나?
- 참고 사항의 허용 언어에 C#이 없는데 제출할 수 있나?
- 등차수열의 합 공식은 무엇인가? 공차는 그냥 곱으로 들어가는가?

## 막혔던 지점
- `money` 상한 10억은 `int` 최대값 2,147,483,647 안에 들어간다. 이용 금액 최댓값은 들어가지 않는다. `2500 × 2500 × 2501 / 2 = 7,815,625,000`. 나누기 전 `15,631,250,000`은 더 크다. `int`로 곱하면 2로 나누기 전에 넘친다.
- 반환형도 `long`이다. `(long)` 캐스트는 첫 곱 앞에 붙인다. 결과를 나중에 캐스트하면 이미 넘친 값이다.
- 참고 사항의 언어 목록은 상품 미션 조건이다. C#으로 푸는 것 자체는 가능하고, 그 상품 대상에서만 빠진다.
- 공차 `d`는 합 전체에 한 번 곱해지는 수가 아니다. `(n - 1) × d`로 마지막 항을 만든다. 이 문제는 첫째 항과 공차가 둘 다 `price`라서 `price × (1 + 2 + … + count)`로 묶인다.

## 문제 한 줄
1번째 `price`, 2번째 `2×price`, … `count`번째까지 탄 총액에서 `money`를 뺀 부족분. 부족하지 않으면 0.

## 핵심 패턴
```text
total = (long)price * count * (count + 1) / 2
total <= money 이면 0
아니면 total - money
```

예시 `price=3`, `count=4`, `money=20`: `3 × 4 × 5 / 2 = 30`, `30 - 20 = 10`.

`count`와 `count + 1`은 연속된 수라 곱이 항상 짝수다. 2로 나누는 위치를 맨 뒤에 두면 나머지가 없다.

등차수열 합: 항 개수 `n`, 첫째 항 `a`, 공차 `d`일 때 `n / 2 × (2a + (n - 1) × d)`. 마지막 항은 `a + (n - 1) × d`. 이 문제는 `a = d = price`, `n = count`.

## 대안별 구현 비교

식은 같고, `int`로 곱하면 최댓값에서 결과가 달라진다.

### A. `long`으로 첫 곱부터
시간 O(1), 추가 메모리 O(1).

```csharp
long total = (long)price * count * (count + 1) / 2;
if (total <= money) return 0;
return total - money;
```

### B. `int`로 곱한 뒤 캐스트
`price`, `count`가 2500이면 곱하는 도중 넘친다. 그 다음 `long`으로 바꿔도 부족한 금액이 틀리다.

```csharp
long total = price * count * (count + 1) / 2;
```

공차가 첫째 항과 다르면 A의 `price × n × (n + 1) / 2`를 쓰면 안 된다. `a = 3`, `d = 5`, `n = 4`의 항은 3, 8, 13, 18이고 합은 42다. `4 / 2 × (2×3 + 3×5) = 42`.

## 다음에 볼 것
- 상한이 10억이어도 곱의 결과가 `int`를 넘을 수 있다. 최댓값을 한 번 계산해 본다.
- 공차는 `(n - 1) × d`로 들어간다. 첫째 항과 공차가 같을 때만 밖으로 묶인다.

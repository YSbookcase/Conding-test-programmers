## 내가 한 질문
- keymap에서 문자별 최소 접근 횟수 표를 만들고, target은 그 합이면 되지 않나?
- 알파벳이 26자인가?
- Dictionary로 생각했는데 `int[26]`은 배열 2개인가, 인덱스를 문자에 대응한 건가?
- keymap을 순회하며 `ch - 'A'` 칸에 넣고, 더 작으면 패스·크면 교체?
- 코드 작성 / `keymap[i]`로 for 접근이 되나?
- 변수는 중괄호 상단에 모으는 게 일반적이지 않나? `answer`가 중간에 있는 이유.
- 코드가 길어지면 모아두기 vs 중간 선언 둘 다 헷갈릴 것 같다.
- LocalTest 코드 검토. `using`은 내가 안 썼다 (VS Community 자동).
- `canType` 플래그로 빠져나가는 구현이 혼자면 시행착오가 있다.
- 성능·일반적으로 개선할 점?

## 막혔던 지점
- `int[26]` 기본값 `0`은 최솟값이 아니라 **없음**. `0 < 횟수`라서 무조건 패스하면 표가 안 채워짐. 비어 있으면 넣기.
- `keymap[i]`는 문자열, 한 글자는 `keymap[i][j]`. 횟수는 `j + 1`.
- 안쪽 `foreach`의 `break`는 글자 루프만 끝남. 문자열 전체 실패는 깃발, `sum = -1`, 또는 함수에서 `return -1`.
- VS가 `using System.ComponentModel` 등을 자동 추가. 제출 시에는 `using System;`만 있으면 됨.

## 문제 한 줄
각 문자를 만드는 **최소 키 누름**을 구한 뒤, target마다 합산. 못 만드는 글자가 있으면 그 문자열은 `-1`.

## 핵심 패턴
```text
minPress[26] = 0 (없음)
keymap[i][j]:
  index = ch - 'A', 횟수 = j + 1
  없거나 더 작으면 minPress[index] = 횟수

target 글자마다:
  0이면 실패(-1)
  아니면 합 += minPress
```
- `Dictionary<char,int>`와 같은 역할. A~Z라서 칸 번호가 문자.
- 표는 keymap에서 **한 번만**. target은 조회만. `O(입력 크기)`.

## 실패 탈출
| 하고 싶은 일 | 쓰기 |
|---|---|
| 이 바퀴만 건너뛰기 | `continue` |
| 이 루프만 끝 | `break` |
| 이 문자열 전체 실패 | `return -1` 또는 `sum = -1` 후 `break` |

`canType`은 이중 루프에서 3번을 흉내 낸 것. 혼자 짤 때는 target 하나를 함수로 보고 `return -1`이 잘 떠오름.

## 변수 위치
- 함수 전체: `minPress` → 상단
- 정답 채우기 구간: `answer` → 표 만든 직후 (지금 제출)
- 루프 한 바퀴: `index`, `pressCount` → 그 루프 안
- 두 구간에서 쓰이면 위로. 너무 길어지면 함수로 나누기.

## 설계 메모
- `0` = 없음은 **횟수가 1 이상일 때만** 안전. 0이 유효하면 `int.MaxValue` / `-1`.
- 키가 A~Z가 아니면 `Dictionary`.
- `int[26]` 사전 계산이 정석. 글자마다 keymap 전체를 찾으면 손해(이 제한에선 통과 가능).

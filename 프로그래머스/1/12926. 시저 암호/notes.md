# 시저 암호 (12926)

## 상태
- 제출 완료. 소문자·대문자를 나눠 `n`칸 밀고 `% 26`. 공백은 그대로
- 제출 파일: `프로그래머스/1/12926. 시저 암호/시저 암호.cs`
- LocalTest는 쓰지 않음

## 내가 한 질문
- `char`와 아스키코드로 밀면 되나?
- 추가로 조언할 점이나 더 좋은 방식이 있나?

## 막혔던 지점
- `'z' - 'a' + n`은 `int`다. `(char)`로 바꿔야 글자가 된다. 정수 그대로 붙이면 이상한 문자 만들기 때처럼 숫자 글자가 나온다. `'z'`를 1칸 밀면 `26 % 26`이 `0`이라 `'a'`다.
- 대문자와 소문자를 같은 기준으로 밀면 `'Z'` 다음이 `'['`가 된다. `'A'`와 `'a'`를 따로 쓴다.
- 공백은 어느 범위에도 넣지 않고 그대로 둔다.
- 알파벳 문자열에서 `IndexOf`로 찾아 밀어도 `"AB"`는 `"BC"`, `"z"`는 `"a"`다. 위치를 찾는 과정이 더 늘어난다. `% 26`이 더 짧다.
- `s`는 `8000`자 이하, `n`은 1 이상 25 이하. 칸마다 한 번만 밀면 된다. 더 줄일 단계는 없다.

## 문제 한 줄
알파벳을 `n`칸 민다. `z` 다음은 `a`, `Z` 다음은 `A`. 공백은 공백이다.

## 핵심 패턴
```text
공백이면 그대로
소문자면 (letter - 'a' + n) % 26 + 'a'
대문자면 (letter - 'A' + n) % 26 + 'A'
결과는 (char)
```
- `"AB"`, `1` → `"BC"`
- `"z"`, `1` → `"a"`
- `"a B z"`, `4` → `"e F d"`

## 대안별 구현 비교

대소문자를 나누고 공백을 유지하면 결과가 같다. `(char)`가 없거나 `'Z'`를 소문자 기준으로 밀면 달라진다. 알파벳 문자열 조회는 답이 같고 찾는 과정만 더 있다.

### A. `'a'`/`'A'`에서 `% 26`
제출한 버전.

```csharp
char[] result = new char[s.Length];
for (int i = 0; i < s.Length; i++)
{
    char letter = s[i];
    if (letter == ' ')
    {
        result[i] = ' ';
    }
    else if (letter >= 'a' && letter <= 'z')
    {
        result[i] = (char)((letter - 'a' + n) % 26 + 'a');
    }
    else
    {
        result[i] = (char)((letter - 'A' + n) % 26 + 'A');
    }
}
return new string(result);
```

### B. 알파벳 문자열에서 위치 찾기
`"AB"`, `1`은 `"BC"`. `"z"`, `1`은 `"a"`. A와 같다. 글자마다 `IndexOf`로 앞부분을 본다.

```csharp
string lower = "abcdefghijklmnopqrstuvwxyz";
string upper = "ABCDEFGHIJKLMNOPQRSTUVWXYZ";
int index = lower.IndexOf(letter);
if (index >= 0)
{
    result[i] = lower[(index + n) % 26];
}
```

대문자도 `upper`로 같은 식이다. 공백은 `IndexOf`가 `-1`이라 그대로 둔다.

### C. `(char)` 없이 밀기
`'z'`를 1칸 민 값 `26`이 글자가 아니라 숫자 문자열로 붙을 수 있다. A는 `(char)`로 `'a'`를 만든다.

### D. 대소문자를 한 범위로
`'Z' + 1`이 `'['`가 된다. A는 `'A'`로 다시 감아 `'A'`가 된다.

## 다음에 볼 것
- 알파벳을 한 바퀴 넘기면 `% 26`으로 처음으로 되돌린다. 대문자와 소문자는 시작 문자가 다르다.
- `char` 연산은 `int`다. 글자로 쓰려면 `(char)`가 필요하다.

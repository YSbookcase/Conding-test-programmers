# x만큼 간격이 있는 n개의 숫자 (12954)

## 상태
- 제출 완료. 길이 `n`인 `long` 배열, `(long)x * (i + 1)`
- 제출 파일: `프로그래머스/1/12954. x만큼 간격이 있는 n개의 숫자/x만큼 간격이 있는 n개의 숫자.cs`
- LocalTest는 쓰지 않음

## 내가 한 질문
- `new long[] { }`에 `answer[i] = x * (i + 1)`을 넣으면 되나?
- `(long)`은 오른쪽 항 앞에만 붙이면 되나?

## 막혔던 지점
- `new long[] { }`은 칸이 0개다. `answer[i]`에 넣으면 범위를 벗어난다. 칸은 `new long[n]`이다.
- `x * (i + 1)`은 둘 다 `int`다. `x`가 10,000,000이고 `i + 1`이 1000이면 10,000,000,000이라 `int` 최대 약 21억을 넘는다. `long` 칸에 넣기 전에 넘친다.
- `(long)`은 바로 뒤의 값 하나에만 붙는다. `(long)x * (i + 1)`은 `x`만 `long`이 된 뒤 곱한다. `(long)(x * (i + 1))`은 곱이 먼저 `int`로 끝나서 넘친 값을 바꾼다.
- 한쪽만 `long`이면 그 곱에서 다른 `int`도 `long`으로 올라간다. `x` 변수 자체는 계속 `int`다.

## 문제 한 줄
`x`부터 `x`씩 증가하는 수를 `n`개 담는다.

## 핵심 패턴
```text
answer = new long[n]
answer[i] = (long)x * (i + 1)
```
- `x = 2`, `n = 5` → `[2, 4, 6, 8, 10]`
- `x = 4`, `n = 3` → `[4, 8, 12]`
- `x = -4`, `n = 2` → `[-4, -8]`
- `n`은 1000 이하. 시간 O(n).

## 대안별 구현 비교

길이 `n`과 첫 곱이 `long`이면 결과가 같다. 빈 배열은 바로 깨지고, 곱한 뒤의 캐스트는 큰 `x`에서 값이 달라진다.

### A. 칸을 `n`개 만들고 먼저 캐스트
제출한 버전.

```csharp
long[] answer = new long[n];
for (int i = 0; i < n; i++)
{
    answer[i] = (long)x * (i + 1);
}
return answer;
```

`(long)(i + 1) * x`도 첫 곱부터 `long`이다.

### B. 빈 배열
`x = 2`, `n = 5`에서도 `answer[0]`에서 범위를 벗어난다.

```csharp
long[] answer = new long[] { };
answer[i] = (long)x * (i + 1);
```

### C. 곱한 뒤에 캐스트
`x = 10000000`, `i + 1 = 1000`이면 10,000,000,000이 아니라 넘친 `int`가 `long`이 된다.

```csharp
answer[i] = (long)(x * (i + 1));
```

앞에서 `int`끼리 곱하면 뒤의 캐스트도 늦다. `a * b * (long)c`는 `a * b`가 먼저 `int`다. `(long)a * b * c`는 첫 곱부터 `long`이다.

나눗셈도 같다. `(long)(a / b)`는 소수점이 이미 버려진 뒤이고, `(long)a / b`는 `long` 나눗셈이다.

## 다음에 볼 것
- 반환이 `long`이어도 곱하는 두 수가 `int`면 먼저 넘친다. 캐스트는 첫 곱 앞에 둔다.
- 배열은 넣을 칸을 `n`개 만든 뒤 인덱스를 쓴다.

## 내가 한 질문
- 1부터 올려 확인하는 게 직관적인데, n이 백만이면 숫자로 봐도 되나? 다른 접근이 필요한가?
- n-1의 약수도 결국 2부터 순차로 보는 것 아닌가? 상한이 n이 아니라 제곱근까지일 뿐이지?
- 작성 확인. 허술해 보이는데 뭔지 모르겠다.

## 막혔던 지점
- 다른 접근은 필수가 아님. n 최대 100만이면 2부터 `n % x == 1`이면 충분. **1부터는 안 됨.** `n % 1`은 항상 0.
- `n % x == 1`은 x가 `n-1`의 약수라는 뜻. 확인은 여전히 2부터 하나씩. 바뀌는 건 상한과, 못 찾으면 `n-1`을 답으로 두는 것.
- 제곱근이 이득인 경우는 답이 `n-1`일 때(`n-1`이 소수). 그냥 올리면 거기까지 가고, 약수로 보면 `sqrt`만 보고 끝.
- 첫 약수에서 `return`하지 않고 `answer = i`로 덮으면 제곱근 이하 **가장 큰** 약수가 남음. `n=100`이면 3이 아니라 9.
- `i * i < n - 1`은 제곱을 놓침. 기사단원과 같이 **이하**. `n=10`이면 9=3*3이라 3을 못 보고 9를 반환.
- `answer == 0` 센티널은 필요 없음. 루프를 다 돌면 `return n - 1`.

## 문제 한 줄
n을 x로 나눈 나머지가 1이 되는 가장 작은 자연수 x. 답은 항상 있다.

## 핵심 패턴
```text
x는 2부터 (1은 나머지 0)
n % x == 1 이면 x
또는
remain = n-1
2부터 i*i <= remain, remain % i == 0 이면 i
없으면 remain
```

예: 10→9의 약수 3, 12→11(소수)이라 11.

## 대안별 구현 비교

둘 다 2부터 나눠 보고 처음 나온 수가 답이다. 차이는 끝까지 가는 최악의 길이.

| | A `n % x == 1` | B `n-1` 약수 + 제곱근 |
|---|---|---|
| 루프 | 2 .. n-1, 찾으면 즉시 | 2 .. `i*i <= n-1`, 없으면 n-1 |
| 답이 작을 때 | 금방 끝 | 같음 |
| 답이 n-1일 때 | n-1까지 | sqrt만 |
| 읽기 | 문제 문장 그대로 | 한 단계 더 |

이번 제한에서는 A도 충분하다. `<`와 `<=`, 덮어쓰기 vs 즉시 return에서 답이 갈린다.

### A. 나머지 그대로 (학습)
```csharp
for (int x = 2; x < n; x++)
{
    if (n % x == 1)
        return x;
}
return n - 1;
```

### B. 제곱근 (LocalTest·학습)
```csharp
int remain = n - 1;
for (int i = 2; i * i <= remain; i++)
{
    if (remain % i == 0)
        return i;
}
return remain;
```

확인: `10 → 3`, `12 → 11`, `100 → 3` (덮어쓰기면 9, `<`면 10에서 9).

## 다음에 볼 것
- 나머지 1 = `n-1`의 약수. 최소는 2 이상 첫 약수.
- 제곱근 루프는 `i * i <= remain`. 첫 약수에서 바로 return.
- n 100만이면 2부터 올려도 통과. 제곱근은 최악일 때만 짧다.

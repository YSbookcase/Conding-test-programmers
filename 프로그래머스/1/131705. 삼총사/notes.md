## 내가 한 질문
- 모든 경우 `13C3`, 세 `for`로 합 0이면 되나? 최선인가?
- 양이 많을 때는 다른 방법을 쓰나? 단계가 두 개고 그다음이 해시·이분·수학인가?
- 정렬 투 포인터. 하나 고정이면 둘은 정렬된 짝인가?
- 해시는? 통이 뭔가. `j`와 필요는? 통을 찾고 없으면 넣나, 커지면 탐색이 비싸지나?
- 다른 사람은 이분 탐색 함수를 쓰더라. DFS인가? `DFS(depth, bool[], start)`는?
- 이분 탐색은 언제부터 유용한가?
- 메모에 투 포인터(왼쪽·오른쪽)·해시, 가능하면 이분 탐색까지.

## 막혔던 지점
- `n ≤ 13`이라 `13C3 = 286`. 三重 `for`가 이 문제의 최선. 인덱스는 `i < j < k` (또는 `i <= Length-3`).
- 번호가 같아도 학생이 다르면 다른 조합. 예3은 값이 겹쳐도 세 합이 0이 안 됨.
- 왼쪽·오른쪽을 좁히는 게 **투 포인터**. 하나 고정 → 나머지 합 `-x`인 짝.
- 해시 통은 `i`와 `j` 사이에서 이미 본 번호. `j`는 값을 한 칸씩 증가. 필요값 `-(number[i]+number[j])`가 통에 있으면 삼총사. **확인 후** 지금 `j`를 통에 넣음.
- `HashSet`은 값당 하나라 같은 번호가 여러 명이면 덜 셀 수 있음. 개수는 `Dictionary`. `HashSet` 탐색은 평균 `O(1)`이라 통이 커져도 선형 탐색처럼 안 느려짐. `List`로 통을 만들면 커질수록 느려짐.
- 이분 탐색 ≠ DFS. `Array.BinarySearch` / 가운데 자르기. `DFS(depth, start)`는 세 명을 고르는 조합 재귀(= 三重 `for`).

## 문제 한 줄
서로 다른 학생 3명의 번호 합이 0인 방법의 수.

## 핵심 패턴 (제출)
```text
i < j < k
number[i] + number[j] + number[k] == 0 이면 +1
```

`n`이 작으면 1단 완전탐색. 커지면 2단(고정 + 2합: 투 포인터 또는 해시). 그다음 도구가 이분 탐색·수학.

## 제출 코드
```csharp
for (int i = 0; i <= number.Length - 3; i++)
    for (int j = i + 1; j <= number.Length - 2; j++)
        for (int k = j + 1; k <= number.Length - 1; k++)
            if (number[i] + number[j] + number[k] == 0)
                answer++;
```

`i <= Length - 3`은 `i < Length - 2`와 같음.

## 대안별 구현 비교

왼쪽·오른쪽을 좁히는 것이 투 포인터가 맞다. 학습 코드는 `삼총사_학습.cs`. 네 방법 결과는 같아야 함. 같은 번호가 여러 명이면 투 포인터는 개수를 곱하고, 해시는 `Dictionary`로 개수를 더하고, 이분은 오른쪽에서 같은 값 개수를 셈.

| | A 三重 for (제출) | B 투 포인터 | C 해시 | D 이분 탐색 |
|---|---|---|---|---|
| 고르는 법 | 세 명 전부 | 1명 고정, 남은 둘을 양 끝 | 1명 고정, 지나온 통 | 2명 고정, 오른쪽에서 하나 |
| 정렬 | 불필요 | 필요 | 불필요 | 필요 |
| 복잡도 | `O(n³)` | `O(n²)` | `O(n²)` | `O(n² log n)` |
| 이 문제 | 최선 | n 클 때 | n 클 때 | 가능하나 투 포인터보다 느림 |

이분은 정렬된 **긴** 목록에서 값을 찾을 때, 또는 “이 제한으로 되나”를 가운데 자를 때 본진이다. 3합에서는 투 포인터가 더 맞다.

### A. 三重 for
제출 코드.

### B. 투 포인터
정렬 후 `x` 고정, `left`/`right` 합이 `-x`가 되게 좁힘. 합이 작으면 `left++`, 크면 `right--`. 맞으면 (왼쪽 값 개수)×(오른쪽 값 개수). 양 끝 값이 같으면 그 구간에서 `C(개수, 2)`.

### C. 해시
`i` 고정, `j`를 오른쪽으로. `need = -(number[i]+number[j])`. 통에 `need` 개수만큼 +1. 그다음 `number[j]`를 통에 넣음.

### D. 이분 탐색
`i < j` 고정, `j+1`~끝에서 `need`의 가장 왼쪽을 이분 탐색한 뒤 같은 값 개수만큼 +1. `Array.BinarySearch`는 하나면 알려 주므로 개수는 따로 셈.

## 다음에 볼 것
- `n` 보고 완전탐색 되는지 먼저.
- 투 포인터 = 정렬 + 왼쪽·오른쪽. 해시 = 같은 2합을 통으로.
- DFS 조합 재귀는 三重 for와 같고, 이분 탐색이 아님.

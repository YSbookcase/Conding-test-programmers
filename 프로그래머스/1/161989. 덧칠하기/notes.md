# 덧칠하기 (161989)

## 상태
- 제출 완료
- 공식 폴더: `프로그래머스/1/161989. 덧칠하기/`

## 내가 한 질문
- `section`만 한 번 순회하면 되지 않나? `section[0] + m - 1`까지 덮고 초과하면 다음 칠.
- 모든 칸(`n`)을 도는 것보다 적게 들지 않나? 더 좋은 방법이 있나?
- 첫 구현 확인 (시작에 `coverEnd`만 잡고 `answer`는 0)
- 지문만 장황하고 실제로는 간단한 문제 아닌가? Lv.0가 더 어려워 보이는데.
- 추가로 주의할 점이 있을까?

## 막혔던 지점
- 첫 칠을 `coverEnd = section[0] + m - 1`로 미리 잡아 놓고 `answer`를 0부터 두면 **횟수가 1 부족**.
- 예1은 2가 아니라 1, 예2는 0, 예3은 3이 나옴.
- 고치려면 `answer = 1`이거나, **최종 제출처럼 `coverEnd = 0`으로 두고 첫 칠도 루프에서 `++`**.

## 문제 한 줄
정렬된 `section`을 왼쪽부터, 아직 안 덮인 칸에서 롤러 `m`을 대며 최소 횟수.

## 핵심 패턴
```text
coverEnd = 0, answer = 0
section 앞에서부터:
  part <= coverEnd → 패스
  아니면 coverEnd = part + m - 1, answer++
```
- 안 덮인 **가장 왼쪽**에서 칠해야 오른쪽으로 가장 멀리 감.
- `n` 전체 순회 불필요. `O(section 길이)`가 최적.
- 끝벽 클램프(`n`)는 **횟수에는 필요 없음**. `coverEnd > n`이어도 남은 칸은 전부 `n` 이하.

## 주의
- `coverEnd`는 `part + m - 1` (`+ m`이면 한 칸 더 덮은 줄 알고 틀림).
- 벽을 `bool[]`로 `m`칸씩 칠하면 `k × m`으로 TLE 가능. 끝 번호만 들고 갈 것.
- 안 벗겨진 칸을 피하려고 롤러를 왼쪽으로 당기지 말 것. 오히려 오른쪽 덮개가 줄어듦.

## 다음에 볼 것
- 지문 길이 ≠ 난이도. 제한사항만 보면 “정렬된 구간 + 고정 길이 최소 덮기”.
- 비슷한 유형: 그리디로 앞에서부터 덮고, 덮인 것은 건너뛰기.

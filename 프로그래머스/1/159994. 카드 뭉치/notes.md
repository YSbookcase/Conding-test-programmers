# 카드 뭉치 (159994)

## 상태
- 제출 완료
- 공식 폴더: `프로그래머스/1/159994. 카드 뭉치/`

## 내가 한 질문
- goal을 돌면서 cards1/cards2와 맞추고, 둘 다 없으면 No, 끝까지 가면 Yes인가?
- 인덱스가 난감하다. 각각 만들어 맞을 때만 올리나? for는 어떻게 구성하나?
- goal은 foreach로 돌아도 되나?
- 다른 문제점 / 추가 조언?
- 큐로 읽으면 양이 많을 때 최적화가 되나?
- `break` / `continue`는 if 안에 있어도 큰 반복문 하나를 나가나?

## 막혔던 지점
- 뭉치 **전체 탐색**이 아님. 건너뛰기 금지라 **맨 앞 한 장만** 비교.
- `for`의 기준은 cards가 아니라 **goal**. 뭉치는 `index1`/`index2`만 맞을 때 +1.
- `cards1[index1]` 전에 `index1 < cards1.Length` 필수 (다 쓴 뭉치).
- `break`는 가장 가까운 루프만 끝냄. if의 대상이 아님. 실패 즉시 끝내려면 `return "No"`.

## 문제 한 줄
두 뭉치를 앞에서만 소비해서 `goal` 순서를 만들 수 있으면 `"Yes"`, 아니면 `"No"`. 남은 카드는 있어도 됨.

## 핵심 패턴
```text
index1 = 0, index2 = 0
foreach word in goal:
  cards1 앞장 == word → index1++
  아니면 cards2 앞장 == word → index2++
  아니면 "No"
끝까지 오면 "Yes"
```
- 단어는 두 뭉치에 겹치지 않음 → `if` / `else if` 순서 무관.
- `Contains`/`IndexOf`로 뒤에서 찾으면 건너뛴 것 → 오답.
- `"Yes"`/`"No"` 문자열. bool 아님.

## 큐 vs 인덱스
- 큐 `Peek`/`Dequeue` = 맨 앞 카드와 같은 뜻. 읽기용.
- 양 많아져도 큐가 더 빠르지 않음. 배열은 이미 있으니 `index++`가 복사 없이 O(1).
- 큐가 이득인 때: 뒤에 넣고 앞에서 빼기를 반복할 때.

## break / continue
| | 대상 |
|---|---|
| `continue` | 가장 가까운 루프의 **이번 바퀴** |
| `break` | 가장 가까운 **루프 전체** (바깥 루프·함수는 그대로) |
| `return` | **함수** |

이중 루프에서 안쪽 `break`만 하면 바깥은 계속 돔 → 그때 깃발이나 `return`.

## 내가 한 질문

- 내적으로 일반적으로 히트 여부를 확인했는가?
- 다른 사람 풀이에 나온 LINQ `Zip`은 무엇인가?

## 막혔던 지점
- 로직은 맞았다. 두 배열의 같은 위치 원소를 곱하고 모두 더하면 문제의 내적 정의 그대로다.
- 두 배열의 길이는 같다고 보장되므로 `a.Length`까지만 순회한다. 한 배열만 정렬하면 같은 위치의 짝이 깨지므로 정렬하지 않는다.
- 한 곱의 절댓값은 최대 `1,000 × 1,000 = 1,000,000`, 원소는 최대 1,000개다. 합의 범위는 -1,000,000,000부터 1,000,000,000까지라 `int`로 안전하다.
- `Select`에는 값과 인덱스를 함께 넘기는 오버로드가 있다. `(value, index)`는 람다식의 매개변수라 바깥에서 인덱스를 선언하거나 증가시키지 않아도 된다. 모든 LINQ 함수가 인덱스를 주는 것은 아니다.
- `Zip`은 두 열거형의 같은 순서 원소를 묶는다. 길이가 다르면 짧은 쪽까지만 처리하지만, 이 문제는 길이가 같다고 보장된다.
- 내적만으로 충돌 여부를 직접 판정하지는 않는다. 내적은 두 벡터의 방향 관계를 보여 준다. 양수면 같은 방향 쪽, 0이면 수직, 음수면 반대 방향 쪽이다. 게임의 히트 판정에서는 앞쪽/공격각 확인에 쓰고, 거리와 Raycast 또는 충돌체를 함께 확인한다.

## 문제 한 줄
같은 길이인 두 배열에서 같은 인덱스의 값을 곱한 결과를 모두 더한다.

## 핵심 패턴
```text
answer = 0
i = 0..a.Length-1
  answer += a[i] * b[i]
return answer
```

시간 O(n), 추가 메모리 O(1).

## 제출 코드
```csharp
int answer = 0;

for (int i = 0; i < a.Length; i++)
    answer += a[i] * b[i];

return answer;
```

`answer`는 지금까지의 곱을 누적한 내적이다. 의미를 더 직접 드러내려면 `dotProduct`라고 할 수 있지만, 이 문제에서는 `answer`도 무난하다.

## 대안별 구현 비교

세 방법 모두 같은 위치끼리 곱한 뒤 더한다. 제출한 `for`문이 할당이 적고 계산 과정이 가장 직접적이다.

### A. `for`문
```csharp
int answer = 0;
for (int i = 0; i < a.Length; i++)
    answer += a[i] * b[i];
return answer;
```

### B. 인덱스가 있는 `Select`
```csharp
return a.Select((value, index) => value * b[index]).Sum();
```

첫 호출은 `(a[0], 0)`, 다음은 `(a[1], 1)`이다. `value`, `index`는 원하는 이름으로 바꿀 수 있다.

### C. 두 열거형을 묶는 `Zip`
```csharp
return a.Zip(b, (aValue, bValue) => aValue * bValue).Sum();
```

예를 들어 `[1,2,3,4]`와 `[-3,-1,0,2]`를 `Zip`하면 곱의 흐름은 `[-3,-2,0,8]`이고, `Sum()` 결과는 3이다. `Select`보다 “두 배열의 같은 위치를 묶는다”는 의도가 직접 드러난다.

`Select`, `Zip`, `Sum`은 `System.Linq`의 확장 함수라 `using System.Linq;`이 필요하다.

## 다음에 볼 것
- 같은 위치끼리 계산하는 두 배열은 기본적으로 인덱스 반복문이나 `Zip`.
- LINQ `Select`는 값과 인덱스를 받는 오버로드가 있다.
- 내적은 히트 자체가 아니라 방향·각도 조건을 판정하는 데 쓴다.

## 막혔던 지점
- 각 가격이 떨어지기 전까지의 초를 세는 것은 맞다. 답 칸 수는 `prices`와 같다. `int[] answer = new int[prices.Length]`로 두고, `List`로 모을 필요가 없다. `new int[]`는 이미 0이라 `Array.Clear`는 없어도 된다.
- 가격이 최대 10만 개라 위치마다 뒤를 모두 보면 비교가 약 50억 번까지 늘어난다. 스택에는 가격이 아니라 아직 안 떨어진 초의 번호를 넣는다. 가격은 `prices[번호]`로 본다.
- `[1, 2, 3, 2, 3]`에서 `1`, `2`, `3`은 스택 `[0, 1, 2]`다. 다음 `2`는 맨 위 `3`보다 작아서 2번을 꺼내고 `3 - 2 = 1`을 2번 칸에 적는다. 그 아래 `2`는 지금 가격과 같아서 더 꺼내지 않는다.
- 그 자리가 `2`가 아니라 `1`이면 `[1, 2, 3, 1, 3]`이다. `3`을 꺼낸 뒤 새 맨 위 `2`도 `1`보다 커서 `1`번까지 꺼낸다. `3 - 1 = 2`라 1번 칸은 2초다. 맨 위가 첫 `1`과 같아지면 `while`이 멈춘다. 답은 `[4, 2, 1, 1, 0]`이다. `2`였을 때의 `[4, 3, 1, 1, 0]`과 다른 칸은 1번 초다.
- 스택 크기는 고정이 아니다. 오르는 동안 늘고, 떨어지면 줄어든다. 계속 오르기만 하면 `prices` 길이와 같아질 수 있다.
- 빼는 두 수는 둘 다 초 번호다. `[5, 8, 10, 7]`에서 `10`이 있던 초는 2번, `7`이 나타난 초는 3번이다. `3 - 2 = 1`을 `10`의 칸인 답 2번에 적는다. `8`은 `3 - 1 = 2`라 답 1번이다. 가격 `10 - 7`이 아니다.
- 바로 다음 초에 떨어져도 그 1초는 센다. `0`은 뒤에 비교할 초가 없는 마지막 칸뿐이다.
- 같은 순간에 두 개가 떨어지는 예는 `[5, 8, 10, 7, 9]`다. `7`에서 `10`과 `8`을 이어서 꺼내고, 답은 `[4, 2, 1, 1, 0]`이다. `5`는 `7`보다 작아서 남는다.
- 떨어진 뒤 나중에 또 떨어지는 예는 `[1, 3, 2, 4, 3]`이다. `2`가 나올 때 `3`만 빠져 1번 칸이 `1`이다. `1`은 스택에 남는다. `4`를 쌓은 뒤 마지막 `3`에서 `4`만 빠져 3번 칸이 `1`이다. `2`는 이번 `3`보다 작아서 남는다. 답은 `[4, 1, 2, 1, 0]`이다.
- `for` 하나는 떨어진 칸만 채운다. 길이는 처음부터 `prices`와 같고, 반복이 길이를 늘리지는 않는다. 뒤 `while`이 스택에 남은 칸만 `마지막 번호 - 그 번호`로 채운다. 마지막 번호는 `prices.Length - 1`이다. 길이에서만 빼면 0번 칸이 한 초 많다.
- `[1, 3, 2, 4, 3]`에서 `for`가 1번과 3번에 `1`을 넣고, `while`이 0번, 2번, 4번에 `4`, `2`, `0`을 넣는다.
- 같은 가격은 떨어진 것이 아니다. 비교는 `>`다. `>=`로 바꾸면 두 번째 `2`에서 1번 칸이 `3`초가 아니라 `2`초가 된다.
- `Peek`은 스택이 비어 있으면 예외다. `Count > 0`을 앞에 둔다. `&&`는 앞이 거짓이면 뒤를 보지 않는다.
- 로컬 프로젝트는 `ImplicitUsings`가 켜져 있어 `using` 없이도 `Stack`이 된다. 프로그래머스 파일에는 `using System.Collections.Generic;`가 있어야 한다.

## 문제 한 줄
각 초의 가격이 떨어지기 전까지의 초. 같은 가격은 떨어짐이 아니다. 길이는 2 이상 10만 이하. `[1, 2, 3, 2, 3]`은 `[4, 3, 1, 1, 0]`.

## 핵심 패턴
```text
answer는 prices와 같은 길이
index를 0부터 끝까지
  스택 맨 위 가격이 지금 가격보다 크면
    그 번호를 꺼내 answer[그 번호] = 지금 번호 - 그 번호
  지금 번호를 스택에 넣는다
스택에 남은 번호는
  answer[번호] = 마지막 번호 - 번호
```

```csharp
while (indexStack.Count > 0 && prices[indexStack.Peek()] > prices[index])
{
    int dropIndex = indexStack.Pop();
    answer[dropIndex] = index - dropIndex;
}

indexStack.Push(index);
```

```csharp
while (indexStack.Count > 0)
{
    int remainIndex = indexStack.Pop();
    answer[remainIndex] = prices.Length - 1 - remainIndex;
}
```

- `[1, 2, 3, 2, 3]` → `[4, 3, 1, 1, 0]`
- `[5, 4, 3, 2, 1]` → `[1, 1, 1, 1, 0]`
- `[1, 3, 2, 4, 3]` → `[4, 1, 2, 1, 0]`

## 대안별 구현 비교

A가 제출본이다. B는 처음 생각한 이중 `for`다. 예제 답은 같다. 차이는 오래 안 떨어지는 입력의 시간이다.

| 풀이 | 시간 | 답 배열 외 공간 | 상승하는 10만 개 |
|---|---|---|---|
| A. 인덱스 스택 | `O(n)` | 스택 `O(n)` | 0.002초. 제출 4.87 ms |
| B. 이중 `for` | `O(n²)` | `O(1)` | 3.3초 |

`n`은 `prices`의 길이. 스택은 번호를 최대 한 번 넣고 한 번 꺼낸다. 이중 `for`는 한 번도 `break`가 없으면 비교가 `n × (n - 1) / 2`, 약 50억 번이다. 바로 다음 초에 매번 떨어지면 B도 `break` 때문에 시간이 `O(n)`에 가까워진다. 효율성 입력은 오래 안 떨어지는 쪽이다.

### B. 이중 `for`

```csharp
int[] answer = new int[prices.Length];

for (int index = 0; index < prices.Length; index++)
{
    for (int later = index + 1; later < prices.Length; later++)
    {
        answer[index]++;
        if (prices[index] > prices[later])
            break;
    }
}

return answer;
```

`answer[index]++`가 `break`보다 앞이라, 바로 다음 초에 떨어져도 1초가 된다. `index`는 그 가격이 있던 초, `later`는 뒤의 초다.

`>`를 `>=`로 바꾸면 같은 가격도 떨어짐이 된다. `[1, 2, 3, 2, 3]`의 1번 칸이 `3`이 아니라 `2`다. 남은 칸을 `prices.Length - remainIndex`로 적으면 0번 칸이 `4`가 아니라 `5`다.

## 다음에 볼 것

- 확인할 답은 `[4, 3, 1, 1, 0]`과 `[1, 1, 1, 1, 0]`이다. 같은 가격에서 꺼내면 1번 칸이 `2`가 된다.

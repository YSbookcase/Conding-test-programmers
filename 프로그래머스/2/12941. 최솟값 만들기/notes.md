## 막혔던 지점
- "k번째를 다시 뽑을 수 없다"는 A의 k번째와 B의 k번째를 같은 순서로 짝지으라는 뜻이 아니다. 각 배열에서 한 번 쓴 숫자는 다시 못 쓴다. 인덱스는 달라도 된다.
- 예제는 합이 최소인 짝 하나를 풀어 쓴 것이다. 길이가 1000이면 짝은 1000!이라 전부 만들 수 없다.
- 자연수는 둘 다 오름차순으로 곱하면 합이 최대다. `[1, 2]`와 `[3, 4]`는 `1×3 + 2×4 = 11`이다. 최소는 한쪽만 반대라 `1×4 + 2×3 = 10`이다.
- `Array.Sort`는 배열 자체의 순서를 바꾼다. 이 문제는 합만 반환하면 된다.
- 원소와 길이가 1000 이하라 합은 최대 10억이다. `int`에 들어간다.
- `Reverse`는 정렬이 아니다. 오름차순으로 만든 배열을 맞바꾸는 한 바퀴다. 끝 인덱스로 읽으면 그 한 바퀴만 빠지고, `Sort` 두 번은 그대로다.

## 문제 한 줄
길이가 같은 두 배열에서 각 숫자를 한 번씩만 짝지어 곱의 합을 최소로 만든다.

## 핵심 패턴
```text
A 오름차순, B 오름차순
끝에서부터 B를 읽어 A[i] * B[길이-1-i]를 더함
```

제출본은 `Reverse`로 B를 뒤집은 뒤 같은 위치끼리 곱한다. 합은 같다.

```csharp
Array.Sort(A);
Array.Sort(B);
Array.Reverse(B);

int sum = 0;

for (int index = 0; index < A.Length; index++)
{
    sum += A[index] * B[index];
}
```

- `[1, 4, 2]`, `[5, 4, 4]` → `29`
- `[1, 2]`, `[3, 4]` → `10`

## 대안별 구현 비교

정렬 두 번은 같다. 차이는 B를 메모리에서 뒤집느냐, 읽을 위치만 바꾸느냐다.

| 방법 | 정렬 | 그 뒤 |
|---|---|---|
| A. `Reverse` 후 같은 인덱스 | A, B 각 한 번 | 뒤집기 한 바퀴. 제출본 |
| B. 끝 인덱스 | A, B 각 한 번 | 뒤집기 없음 |

### B. 끝 인덱스

```csharp
public int solution(int[] A, int[] B)
{
    Array.Sort(A);
    Array.Sort(B);

    int sum = 0;

    for (int index = 0; index < A.Length; index++)
    {
        sum += A[index] * B[B.Length - 1 - index];
    }

    return sum;
}
```

## 다음에 볼 것
- 순서가 필요하면 정렬이다. 비교 정렬의 일반 비용은 `n log n`이고 `Array.Sort`가 그 계열이다.
- 한 번만 찾는 문제는 훑는다. 여러 번 찾으면 `HashSet`이나 `Dictionary`, 범위가 필요하면 정렬 뒤 이진 탐색이다.
- 최댓값·최솟값처럼 한 번만 보면 되는 문제에 정렬부터 하지 않는다.

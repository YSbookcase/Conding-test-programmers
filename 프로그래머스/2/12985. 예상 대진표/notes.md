## 내가 한 질문
- 짝수면 2로 나누고, 홀수면 1을 더한 뒤 2로 나누면서, `b - a`가 1이면 반복을 끝내고 카운터를 반환하면 되나? 로컬 코드를 확인해 달라
- 첫 풀이에 헛점이 많아 보인다

## 막혔던 지점
- 번호를 줄이는 계산은 맞았다. 홀수면 `+ 1`한 뒤 나누고, 짝수면 그대로 나누는 것은 둘 다 `(번호 + 1) / 2`다. 이 값이 다음 라운드 번호다.
- 예제 `4`, `7`은 `2, 4` → `1, 2`가 된 뒤 차이가 1이라 `++answer`까지 더해 `3`이 나왔다. 예제만 보면 끝나는 조건도 맞아 보였다.
- `b - a == 1`은 번호가 붙어 있으면 이번 라운드에 만난다고 읽힌다. 같은 경기는 `1-2`, `3-4`처럼 앞 번호가 홀수인 쌍이다. `2`와 `3`은 차이가 1이지만 1라운드에서 `2`는 `1`과, `3`은 `4`와 붙는다. 다음 번호가 `1`, `2`가 된 뒤 2라운드에서 만난다. 첫 코드는 반복에 들어가지 않고 `1`을 반환했다.
- `4`와 `5`도 시작 차이가 1이라 첫 코드는 `1`이다. 만나는 라운드는 `3`이다.
- `a`가 `b`보다 크면 `b - a`는 음수라 1이 되지 않는다. `7`, `4`는 둘 다 `1`이 된 뒤에도 반복이 끝나지 않았다.
- 같은 경기는 둘 다 `(번호 + 1) / 2`를 하면 같은 수가 된다. 그 순간까지 센 횟수가 라운드다. `4`, `7`은 `2, 4` → `1, 2` → `1, 1`이라 `3`이다. `a`와 `b`의 순서는 이 조건에서 상관없다.
- `N`은 2의 거듭제곱이라 부전승이 없다. 둘은 항상 이긴다고 하므로 다른 참가자의 승패는 보지 않는다.

## 문제 한 줄
항상 이기는 `A`와 `B`가 토너먼트에서 만나는 라운드. `N`은 2의 거듭제곱. 예제 `8, 4, 7`은 `3`.

## 핵심 패턴
```text
a와 b가 다를 동안
  a = (a + 1) / 2
  b = (b + 1) / 2
  라운드 1 증가
라운드 반환
```

```csharp
int answer = 0;

while (a != b)
{
    a = (a + 1) / 2;
    b = (b + 1) / 2;
    answer++;
}

return answer;
```

- `4, 7` → `3`
- `7, 4` → `3`
- `2, 3` → `2`
- `1, 2` → `1`
- `4, 5` → `3`

## 대안별 구현 비교

A가 제출본이다. B는 번호 차이가 1이면 그 라운드에 만난다고 본 첫 로컬이다. `4, 7`만 같고, 붙어 있지만 다른 경기인 쌍과 `a`가 더 큰 경우에 갈라진다.

| 방법 | `4, 7` | `2, 3` | `4, 5` | `7, 4` |
|---|---|---|---|---|
| A. 다음 번호가 같아질 때까지 | `3` | `2` | `3` | `3` |
| B. `b - a == 1`이면 종료 | `3` | `1` | `1` | 반복이 끝나지 않음 |

### B. 차이가 1이면 종료

```csharp
int answer = 0;

while (b - a != 1)
{
    a = a % 2 == 1 ? (a + 1) / 2 : a / 2;
    b = b % 2 == 1 ? (b + 1) / 2 : b / 2;
    answer++;
}

return ++answer;
```

홀수 분기와 짝수 분기는 `(번호 + 1) / 2`와 같다. `return ++answer`는 차이가 이미 1인 라운드를 반복 밖에서 한 번 더 센다. `1, 2`처럼 처음부터 같은 경기면 `1`이 맞아 떨어진다. `2, 3`도 차이가 1이라 같은 식으로 `1`이 된다.

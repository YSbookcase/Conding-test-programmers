## 내가 한 질문
- 하루에 `speed`를 더해 100 이상이면 끝난다고 보면 되나? 리턴은 어떻게 만들지 모르겠다
- `(100 - progress + speed - 1) / speed`에서 `speed`를 더하는 이유는 알겠는데 `- 1`은 무엇인가?
- `deployDay`는 무슨 의미인가?
- 추가로 볼 점이 있나?
- 풀이를 따라가기가 힘들었다

## 막혔던 지점
- 리턴은 배포 한 번에 같이 나가는 기능 개수다. 횟수를 미리 알 수 없어 `List`에 넣고 `ToArray`로 바꾼다. 예제 1은 `[2, 1]`, 예제 2는 `[1, 3, 2]`다.
- 하루씩 더해도 기능이 100개 이하라 계산은 끝난다. 각 기능이 끝나는 날만 구하면 같은 묶음이 된다. 앞 기능보다 먼저 나갈 수 없다.
- 정수 나눗셈은 소수점을 버린다. `70 / 30`은 `2`지만 실제는 3일이다. 나누기 전에 `speed - 1`을 더하면 버림이 올림이 된다. `(70 + 30 - 1) / 30 = 99 / 30 = 3`이다.
- `- 1`은 딱 나누어떨어지는 날을 하루 늘리지 않는다. 남은 작업 `60`, 속도 `30`은 정확히 2일이다. `- 1`이 없으면 `(60 + 30) / 30 = 3`이 된다. `- 1`이 있으면 `89 / 30 = 2`다.
- 진도 `95`, 속도 `4`의 남은 작업은 `5`다. `(5 + 4 - 1) / 4 = 2`라 문제 설명의 2일 뒤 배포와 같다.
- `deployDay`는 지금 묶음이 나가는 날이다. 그 묶음 맨 앞 기능이 끝나는 날로 정한다. 예제 1의 남은 날은 `7, 3, 9`다. `3`은 `7` 이전에 끝나 함께 나가고, `9`는 새 배포일이 된다.
- 예제 2의 남은 날은 `5, 10, 1, 1, 20, 1`이다. `deployDay`는 `5` → `10` → `20`이다. 세 번째 기능은 1일이면 끝나도 앞의 10일이 막을 때까지 기다린다. 남은 날만 정렬하면 이 순서가 깨진다.
- `remainDay <= deployDay`여야 같은 날 끝나는 기능이 함께 나간다. `<`만 쓰면 둘 다 7일인 `[93, 93]`, `[1, 1]`이 `[2]`가 아니라 `[1, 1]`이 된다.
- 반복 안의 `Add`는 더 오래 걸리는 기능을 만났을 때만 이전 묶음을 넣는다. 마지막 묶음은 반복 뒤의 `answer.Add(count)`다. 예제 1의 `1`, 예제 2의 `2`가 거기서 들어간다. 기능이 하나면 `for`가 돌지 않고 이 줄만으로 `[1]`이 된다.
- `for`는 `index = 1`부터다. 첫 기능은 이미 `count = 1`, `deployDay`로 세어 두었다.
- 로컬은 `ImplicitUsings` 때문에 `List`가 된다. 프로그래머스에는 `using System.Collections.Generic;`가 필요하다.

## 문제 한 줄
앞에 있는 기능이 끝나야 뒤 기능이 함께 배포된다. 배포마다 같이 나가는 개수를 반환한다. 기능은 100개 이하, 진도는 100 미만이다.

## 핵심 패턴
```text
첫 기능의 남은 날을 deployDay로 두고 count = 1
다음 기능부터
  남은 날 <= deployDay면 count++
  더 늦으면 지금까지 count를 넣고, deployDay와 count를 새 기능으로
반복이 끝나면 마지막 count를 넣는다
남은 날 = (100 - progress + speed - 1) / speed
```

```csharp
int remainDay = (100 - progresses[index] + speeds[index] - 1) / speeds[index];

if (remainDay <= deployDay)
    count++;
else
{
    answer.Add(count);
    deployDay = remainDay;
    count = 1;
}
```

- `[93, 30, 55]`, `[1, 30, 5]` → 남은 날 `7, 3, 9` → `[2, 1]`
- `[95, 90, 99, 99, 80, 99]`, 속도 전부 `1` → `5, 10, 1, 1, 20, 1` → `[1, 3, 2]`
- 기능 하나 → `[1]`

시간은 `O(n)`, 배포 목록은 최대 `n`개라 공간도 `O(n)`이다.

## 대안별 구현 비교

A가 제출본이다. B는 하루씩 진도를 더한다. 예제 답은 같다. `- 1`을 빼거나 같은 날을 `<`로 비교하면 묶음이 갈라진다.

| 방법 | 시간 | 공간 | 예제 1 |
|---|---|---|---|
| A. 남은 날로 묶기 | `O(n)` | 목록 `O(n)` | `[2, 1]`. 제출본 |
| B. 하루씩 더하기 | `O(n × 최대 일수)` | 목록 `O(n)` | `[2, 1]` |
| `- 1` 없이 올림 | 남은 날이 정확한 배수에서 하루 큼 | | 진도 `95` 속도 `3`, 진도 `40` 속도 `30`은 `[2]`가 아니라 `[1, 1]` |
| `<=` 대신 `<` | 같은 날이 새 배포 | | `[93, 93]`, `[1, 1]`은 `[2]`가 아니라 `[1, 1]` |

### B. 하루씩 더하기

```csharp
List<int> answer = new List<int>();
int index = 0;
int day = 0;

while (index < progresses.Length)
{
    day++;
    int count = 0;

    while (index < progresses.Length &&
           progresses[index] + speeds[index] * day >= 100)
    {
        count++;
        index++;
    }

    if (count > 0)
        answer.Add(count);
}

return answer.ToArray();
```

앞 기능이 100이 되기 전에는 `index`가 멈추므로, 뒤에 빨리 끝난 기능도 그 날까지 기다린다. 최대 일수는 100 미만이라 `O(n × 최대 일수)`도 이 제한에서는 충분하다. A는 기능마다 나눗셈 한 번이다.

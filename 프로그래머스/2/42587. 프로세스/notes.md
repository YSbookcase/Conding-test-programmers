## 내가 한 질문
- 우선순위가 가장 높고 앞에 있으면 먼저 나가고, 아니면 높았던 것의 뒤로 가는 문제인가?
- `continue`를 타면 `order++`가 안 되나?
- `Dequeue`된 인덱스가 `location`과 같을 때 지금까지의 `order`를 반환하는 건가?

- `<(int index, int priority)>` 선언이 익숙하지 않다
- 배열이 아닌데 칸에 값이 여러 개 들어가는 형태가 눈에 익지 않다
- 자료형은 무엇인가?
- 괄호로 표현되는 자료형은 무엇인가?
- 튜플의 유용한 특징은? 다른 언어와 비교해 예전에 물어봤나?

## 막혔던 지점
- 맨 앞이 지금 큐에서 가장 높을 때만 실행되고 빠진다. 뒤에 더 높은 것이 있으면 맨 앞은 실행되지 않고 맨 뒤로 간다. 높은 우선순위가 줄을 뛰어넘지는 않는다.
- `[2, 1, 3, 2]`, `location` 2는 `C`다. `[A2, B1, C3, D2]`에서 `A`와 `B`가 뒤로 간 뒤 `C`가 맨 앞에서 실행된다. 1번째라 답은 `1`이다. 이어서라면 `D`, `A`, `B`다. `D`와 `A`는 우선순위가 같아서 앞에 있는 `D`가 먼저다.
- `[1, 1, 9, 1, 1, 1]`, `location` 0은 `A`다. `C` 다음 `D, E, F, A, B` 순이라 `A`는 5번째다.
- `continue`는 그 바퀴의 남은 코드를 건너뛴다. 뒤로 보낸 프로세스는 `order++`와 `location` 비교를 하지 않는다. `order`는 실행이 확정된 뒤에만 오른다.
- `index == location`은 꺼낸 직마다가 아니다. 더 높은 프로세스가 없어 실행될 때, 방금 올린 `order`를 반환한다.
- `return order`가 `while` 안에만 있으면 컴파일러는 반복이 끝나도 값을 못 돌리는 경로가 있다고 본다. `location`은 반드시 한 번 실행되므로 실제 예제는 위의 `return`으로 나간다. `while` 뒤에 `return order`를 두어 컴파일을 통과했다.
- 우선순위만 큐에 넣으면 `[2, 1, 3, 2]`에서 앞의 `2`를 뒤로 보낸 뒤 어느 `2`가 `location`인지 사라진다. 칸 하나에 처음 위치와 우선순위를 같이 넣는다. `(0, 2), (1, 1), (2, 3), (3, 2)`다.
- `(int index, int priority)`는 값 튜플 `ValueTuple<int, int>`다. 큐 자료형은 `Queue<(int index, int priority)>`다. 넣을 때 묶고 꺼낼 때 두 변수로 푼다.
- 길이 2인 `int[]`도 같은 줄이다. `0`번이 위치, `1`번이 우선순위다. 튜플은 `process[0]` 대신 `index`로 읽는다.
- 10월 9일 게임 맵에서 물은 것은 튜플인지, 왜 그 자료형인지, 수정이 안 되는지가다. 다른 언어와 비교해 달라고 한 적은 없다. 그때 답에서 파이썬 튜플이 불변이라는 말과, C#의 예전 `Tuple` 클래스가 `Item1`만 되고 내용을 못 바꾼다는 말이 나왔다.
- 지금 값 튜플은 지역 변수로 꺼낸 뒤 필드를 대입할 수 있다. 큐에 들어 있는 칸은 복사본이라 꺼낸 변수를 고쳐도 큐 안은 그대로다. 뒤로 보낼 때는 새 `(index, priority)`를 넣는다.
- 프로세스는 100개 이하다. 꺼낼 때마다 큐를 한 번 보므로 시간은 `O(n²)`, 큐 공간은 `O(n)`이다.

## 문제 한 줄
맨 앞을 꺼내 더 높은 우선순위가 있으면 맨 뒤로, 없으면 실행한다. `location` 프로세스가 몇 번째로 실행되는지 반환한다. 우선순위는 1 이상 9 이하이고 클수록 높다.

## 핵심 패턴
```text
큐에 (처음 위치, 우선순위)를 순서대로 넣는다
큐가 빌 때까지
  맨 앞을 꺼낸다
  뒤에 더 높은 우선순위가 있으면 맨 뒤에 다시 넣고 continue
  없으면 order를 1 올리고, 위치가 location이면 order 반환
```

```csharp
if (hasHigher)
{
    waiting.Enqueue((index, priority));
    continue;
}

order++;
if (index == location)
    return order;
```

- `[2, 1, 3, 2]`, `location` 2 → `1`
- `[1, 1, 9, 1, 1, 1]`, `location` 0 → `5`

## 다음에 볼 것
- 백지에서는 `(index, priority)`를 넣고, 실행이 확정된 뒤에만 `order`를 올린다.
- 확인할 답은 위치 2의 `1`, 위치 0의 `5`다. 우선순위가 같은 두 프로세스는 앞에 있던 쪽이 먼저다.
- 게임 맵 메모의 값 튜플과 같은 자료형이다. 칸 내용만 행, 열, 거리에서 위치, 우선순위로 바뀐다.

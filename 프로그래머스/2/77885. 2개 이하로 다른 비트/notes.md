## 막혔던 지점
- `x + 1`부터 올려 가며 다른 비트 개수를 세면 안 된다. 수는 `10^15`, 배열 길이는 10만이라 수마다 상수·로그 시간에 구해야 한다.
- 짝수는 맨 아래(값 1)가 0이다. 그 비트만 1로 바꾸면 `number + 1`이고, 다른 비트가 1개다. `f(2) = 3`.
- 홀수는 맨 아래가 이미 1이라 한 자리만 켜서 “더 작으면서 큰 수”를 만들기 어렵다. 오른쪽(작은 자리)부터 본 **첫 0**을 1로 켜고, **그 바로 오른쪽(한 자리 더 작은 쪽) 1**을 0으로 끈다. 비트가 정확히 2개 바뀐다.
- “가장 아래쪽”은 십진 첫 자리가 아니다. 비트를 `… 8 4 2 1`처럼 쓰면 오른쪽이 작은 자리고, 오른쪽부터 스캔해 처음 나오는 0이다. “바로 오른쪽”은 그 0보다 값 절반인 칸이다.
- `7 = 0111`이면 첫 0은 8의 자리, 바로 오른쪽은 4의 자리 → `1011 = 11`. `9 = 1001`이면 첫 0은 2의 자리, 바로 오른쪽은 1의 자리 → `1010 = 10`. `11`은 비트 1개만 다르지만 `10`보다 커서 `f(9) = 10`이다.
- `&`는 둘 다 1일 때만 1이라 “그 자리가 켜져 있는지” 본다. `|`는 하나라도 1이면 1이라 “그 자리를 켠다”. `bit <<= 1`은 자리값을 두 배로 한 칸 왼쪽으로 옮긴다.
- `while ((number & bit) != 0)`은 `bit` 자리가 1이면 계속 옮기고, 0이면 멈춘다. 그때의 `bit`가 첫 0의 자리값이다. `(number | bit) - (bit >> 1)`이 켜고 오른쪽을 끄는 연산이다.

## 문제 한 줄
`numbers`의 각 수 `x`에 대해, `x`보다 크고 비트가 1~2개만 다른 수 중 최솟값 `f(x)`를 담아 반환한다. 길이는 10만, 각 수는 `10^15` 이하.

## 핵심 패턴
```text
짝수면 number + 1
홀수면
  bit = 1부터, number와 겹치면 bit를 왼쪽으로
  (number | bit) - (bit >> 1)
```

```csharp
long NextNumber(long number)
{
    if (number % 2 == 0)
        return number + 1;

    long bit = 1;
    while ((number & bit) != 0)
        bit <<= 1;

    return (number | bit) - (bit >> 1);
}
```

| number | f |
|---|---|
| 0 | 1 |
| 1 | 2 |
| 2 | 3 |
| 7 | 11 |
| 9 | 10 |
| `[2, 7]` | `[3, 11]` |

## 대안별 구현 비교

답은 같다. 제출본은 첫 0 자리를 `bit`로 찾고, 한 줄 식은 `+1`로 뒤집힌 구간을 XOR로 잰 뒤 같은 값을 만든다.

짝수면 `number ^ (number + 1)`이 `1`이라 `>> 2`가 `0`이고, 결과는 `number + 1`이다. 홀수 `7`은 `7 ^ 8 = 15`, `15 >> 2 = 3`, `8 + 3 = 11`이다. 읽기에는 `bit`를 찾는 쪽이 직접적이다.

| 방법 | 계산 | 메모 |
|---|---|---|
| A. bit 탐색 | 짝수 `+1`, 홀수 켜고 오른쪽 끄기 | 제출본 |
| B. XOR 한 줄 | `number + 1 + ((number ^ (number + 1)) >> 2)` | 짝·홀 동일 식 |

### B. XOR 한 줄

```csharp
long NextNumber(long number)
{
    return number + 1 + ((number ^ (number + 1)) >> 2);
}
```

XOR은 같은 자리에서 비트가 같으면 0, 다르면 1이다.

## 다음에 볼 것

- 제출본의 `bit`는 오른쪽에서 본 첫 0의 자리값이고, `bit >> 1`은 그 바로 오른쪽 자리값이다.

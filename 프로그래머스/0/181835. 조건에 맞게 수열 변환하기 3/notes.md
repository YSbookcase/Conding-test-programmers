# 조건에 맞게 수열 변환하기 3 (181835)

## 내가 한 질문
- `k`가 홀수면 곱하기, 짝수면 더하기 조건을 `for`문으로 처리하는 접근이 맞는가?
- `k % 2` 검사를 루프 밖으로 빼는 것이 더 나은가?
- `for`문 구조가 같으니 하나로 묶는 것이 좋은가, 아니면 루프 2개로 나누는 것이 좋은가?
- 삼항 연산자와 `if`의 성능 차이는 있는가?

## 막혔던 지점 및 개념 정리
- **문제 핵심**:
  - `k`가 홀수 → 모든 원소에 `k` 곱하기
  - `k`가 짝수 → 모든 원소에 `k` 더하기
- **초기 풀이 개선점**:
  - 루프 안에서 매번 `if (k % 2 != 0)` 검사 → `k`는 변하지 않으므로 **루프 밖에서 1번만 판별**하는 것이 더 좋음.
- **루프 2개 vs 루프 1개**:
  - **루프 2개 분리**: 루프 내부 분기 없음, 연산이 완전히 다를 때 의도가 분명함.
  - **루프 1개 + `bool isOdd`**: `for` 중복 제거, 코드가 더 짧음.
  - 둘 다 `k` 판별을 루프 밖에서 1번만 하면 충분히 좋은 풀이.
- **대용량 배열(최대 100만)에서 `for` vs LINQ**:
  - `for` + in-place 수정: 새 배열 생성 없음, 메모리/GC 부담 적음 → **이 문제에 적합**.
  - LINQ `Select().ToArray()`: 새 배열 생성으로 100만 원소 시 메모리 부담 증가.
- **삼항 연산자 vs `if`**:
  - 성능 차이는 사실상 없음 (둘 다 분기 발생).
  - 삼항 연산자: 값 하나를 조건에 따라 대입할 때 간결.
  - `if`: 여러 줄 실행, 복잡한 조건일 때 명시적.
  - **선택 기준은 가독성과 스타일**.

## 핵심 코드

### 1. 루프 2개로 분리 (최종 제출 ⭐)
```csharp
public class Solution {
    public int[] solution(int[] arr, int k) {
        if (k % 2 != 0) {
            for (int i = 0; i < arr.Length; i++) {
                arr[i] *= k;
            }
        } else {
            for (int i = 0; i < arr.Length; i++) {
                arr[i] += k;
            }
        }
        return arr;
    }
}
```

### 2. 루프 1개 + 삼항 연산자 (동등하게 좋은 대안)
```csharp
public class Solution {
    public int[] solution(int[] arr, int k) {
        bool isOdd = k % 2 != 0;

        for (int i = 0; i < arr.Length; i++) {
            arr[i] = isOdd ? arr[i] * k : arr[i] + k;
        }

        return arr;
    }
}
```

### 3. LINQ (가독성은 좋지만 대용량에 비추천)
```csharp
using System.Linq;

return k % 2 != 0
    ? arr.Select(x => x * k).ToArray()
    : arr.Select(x => x + k).ToArray();
```

## 풀이 방식 비교
| 방식 | 루프 내부 분기 | `for` 중복 | 대용량 적합 | 추천 |
|---|---|---|---|---|
| **루프 2개 (최종 제출 ⭐)** | 없음 | 있음 | ⭕ | 연산 경로가 명확할 때 |
| **루프 1개 + 삼항** | 있음 | 없음 | ⭕ | 코드 간결함 우선 |
| **루프 안 `k % 2` 검사** | 매 원소마다 | 없음 | ⭕ | 비효율적, 비추천 |
| **LINQ `Select`** | - | - | ❌ | 100만 원소 시 메모리 부담 |

## 다음에 볼 것
- 변하지 않는 조건(`k` 홀짝)은 **루프 밖에서 1번만** 판별
- 배열 길이가 클 때(10만+)는 **in-place `for`문** 우선, LINQ는 신중히 사용
- 삼항 연산자 vs `if`는 **성능보다 가독성** 기준으로 선택

# 문자열로 변환 (181845)

## 내가 한 질문
- 숫자를 문자열로 변환할 때 `string.TryParse` 같은 메서드가 있는가?
- 문자열 보간(`$"{n}"`)은 C# 버전에 상관없이 사용 가능한가? (Python 2 vs 3 차이처럼)
- 과거 버전 코드를 최신 버전으로 컴파일해도 문제없는가?
- 코드를 최신 버전에 맞춰 모던(Modern)하게 리팩토링하는 이유와 보안 관련성은 무엇인가?

## 막혔던 지점 및 개념 정리
- **`string.TryParse`가 없는 이유**:
  - `int.TryParse`처럼 **"문자열 ➔ 숫자"** 변환은 잘못된 형식("abc")으로 인해 실패할 가능성이 있어 `TryParse`가 필요함.
  - 반면 **"숫자 ➔ 문자열"** 변환은 어떤 정수든 문자열로 변환 시 실패할 가능성이 100% 없으므로 `TryParse` 자체가 존재하지 않음.
- **숫자를 문자열로 변환하는 대표적인 4가지 방법**:
  1. `n.ToString()`: 가장 표준적이고 빠른 방법 (최종 제출 ⭐)
  2. `$"{n}"`: C# 6.0부터 도입된 문자열 보간(String Interpolation), 가독성 우수
  3. `Convert.ToString(n)`: `null` 안전성이 필요한 객체 변환 시 유용
  4. `n + ""`: 빈 문자열 덧셈 (간단하지만 불필요한 임시 객체 생성 주의)
- **C# 하위 호환성 및 모던 리팩토링/보안의 이유**:
  - **하위 호환성**: C#은 이전 버전 코드도 최신 런타임에서 대부분 문제없이 컴파일 및 실행 지원.
  - **모던 리팩토링 이유**:
    1. **성능 및 비용 절감**: 최신 .NET 런타임 최적화와 메모리 할당(GC) 감소로 클라우드 인프라 비용 절감.
    2. **가독성 및 생산성**: 코드가 간결해져 버그 발생 감소.
    3. **보안(Security)**: 구버전 프레임워크 지원 종료(EOL) 대응, 취약한 구형 API 제거, 최신 보안 프로토콜(TLS 1.3 등) 지원.

## 핵심 코드

### 1. `ToString()` 활용 (표준 풀이 - 최종 제출 ⭐)
```csharp
public class Solution {
    public string solution(int n) {
        // 숫자를 문자열로 변환
        return n.ToString();
    }
}
```

### 2. 문자열 보간(`$""`) 활용 (모던 C# 6.0+ 풀이)
```csharp
public class Solution {
    public string solution(int n) {
        // 문자열 보간을 이용한 간결한 변환
        return $"{n}";
    }
}
```

## 타입 변환 메서드 요약
| 변환 방향 | 추천 메서드 | 비고 |
|---|---|---|
| **문자열 ➔ 정수** | `int.TryParse(s, out int n)` | 실패 가능성 있음 (`false` 반환) |
| **정수 ➔ 문자열** | `n.ToString()` 또는 `$"{n}"` | 실패 가능성 없음 (항상 성공) |

## 다음에 볼 것
- 숫자를 문자로 바꿀 때는 고민 없이 `.ToString()` 또는 `$"{n}"` 사용
- 코딩테스트 플랫폼(프로그래머스 등)은 최신 .NET 환경이므로 최신 C# 문법을 자유롭게 활용 가능

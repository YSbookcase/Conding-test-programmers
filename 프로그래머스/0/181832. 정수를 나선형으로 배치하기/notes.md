# 정수를 나선형으로 배치하기 (181832)

## 내가 한 질문
- 행마다 규칙을 찾는 접근과 꺾이는 지점의 규칙을 찾는 접근이 맞는가? 어떤 방법을 추천하는가?
- 방향 시뮬레이션은 각 위치마다 방향 특성을 미리 구하는 방법인가?
- 레이어 채우기와는 무엇이 다른가?
- 결국 배열 위 위치 `(x, y)`를 구하는 것이 맞는가?
- 핵심 알고리즘과 `dir`의 의미·변화 방식은?
- Level 0치고 좌표를 쓰는 복잡한 문제 아닌가?
- `int dx = {...}` 오타의 원인은?
- 방향 시뮬레이션 외 다른 방법은? 수학 공식이 필요한 경우가 있나?

## 막혔던 지점 및 개념 정리
- **문제 본질**: `1 ~ n²`를 `n × n` 배열에 시계방향 나선으로 배치. 결국 **각 숫자의 좌표 `(x, y)`를 정하는 문제**.
- **비추천 접근**:
  - 행마다 규칙을 공식화 → `n`이 바뀌면 패턴이 복잡해져 실수 많음.
  - 꺾임 지점만 따로 공식화 → 경계/이미 채운 칸 처리에서 오류 나기 쉬움.
- **추천: 방향 시뮬레이션 ⭐**:
  - 각 칸에 방향을 미리 적어두는 방식이 **아님**.
  - **현재 위치 `(x, y)` + 현재 방향 `dir`**을 들고, 한 칸씩 채우다가 막히면 시계방향 회전.
  - `dir`: 0 오른쪽, 1 아래, 2 왼쪽, 3 위.
  - `dx/dy`: 그 방향으로 갈 때 행/열 변화량.
  - 회전: `dir = (dir + 1) % 4` (막혔을 때만).
- **대안: 레이어(테두리) 채우기**:
  - 한 칸씩이 아니라 **바깥 테두리 → 안쪽 테두리** 순으로 한 겹씩 채움.
  - 상태: `top, bottom, left, right` 경계를 좁혀감.
  - 시뮬레이션과 결과는 같고, **진행 단위만 “칸” vs “테두리”** 차이.
- **수학 공식**:
  - 일반 배열 채우기 문제에서는 불필요 (`n ≤ 30`이면 시뮬레이션/레이어로 충분).
  - `n`이 초거대이고 특정 좌표만 물을 때만 레이어 기반 위치 계산/공식을 검토.
- **오타 주의**: `int dx = {...}` ❌ → `int[] dx = {...}` ⭕ (`dx`/`dy`는 길이 4 배열).
- **난이도 체감**: Level 0이지만 좌표·방향·경계 체크가 묶여 **격자 시뮬레이션 입문**에 가깝다. 어렵게 느껴지는 것이 정상.

## 핵심 코드

### 1. 방향 시뮬레이션 (최종 제출 ⭐)
```csharp
public class Solution {
    public int[,] solution(int n) {
        int[,] answer = new int[n, n];

        // dir: 0 오른쪽, 1 아래, 2 왼쪽, 3 위
        int[] dx = { 0, 1, 0, -1 };
        int[] dy = { 1, 0, -1, 0 };

        int x = 0, y = 0, dir = 0;

        for (int num = 1; num <= n * n; num++) {
            answer[x, y] = num;

            int nx = x + dx[dir];
            int ny = y + dy[dir];

            // 범위 밖이거나 이미 채워진 칸이면 시계방향 회전
            if (nx < 0 || nx >= n || ny < 0 || ny >= n || answer[nx, ny] != 0) {
                dir = (dir + 1) % 4;
                nx = x + dx[dir];
                ny = y + dy[dir];
            }

            x = nx;
            y = ny;
        }

        return answer;
    }
}
```

### 2. 레이어(테두리) 채우기 (대안)
```csharp
int num = 1;
int top = 0, bottom = n - 1, left = 0, right = n - 1;

while (num <= n * n) {
    for (int y = left; y <= right; y++) answer[top, y] = num++;
    top++;

    for (int x = top; x <= bottom; x++) answer[x, right] = num++;
    right--;

    if (top <= bottom) {
        for (int y = right; y >= left; y--) answer[bottom, y] = num++;
        bottom--;
    }

    if (left <= right) {
        for (int x = bottom; x >= top; x--) answer[x, left] = num++;
        left++;
    }
}
```

## 방법 비교
| 방식 | 단위 | 상태 | 추천 |
|---|---|---|---|
| **방향 시뮬레이션 (최종 제출 ⭐)** | 한 칸씩 | `x, y, dir` | 격자 이동 연습, 구현 단순 |
| **레이어 채우기** | 한 테두리씩 | `top/bottom/left/right` | 경계 개념이 익숙할 때 |
| **행/꺾임 공식화** | 수식 | - | 비추천 (복잡·실수 많음) |
| **순수 수학 공식** | 좌표 → 값 | - | 초거대 n + 일부 좌표만 질문할 때 |

## `dir` / `dx` / `dy` 요약
| `dir` | 방향 | `dx` | `dy` | 다음 칸 |
|---|---|---|---|---|
| 0 | 오른쪽 | 0 | 1 | `(x, y+1)` |
| 1 | 아래 | 1 | 0 | `(x+1, y)` |
| 2 | 왼쪽 | 0 | -1 | `(x, y-1)` |
| 3 | 위 | -1 | 0 | `(x-1, y)` |

- 반복문: `for (int num = 1; num <= n * n; num++)` (채울 개수가 고정)
- 평소: `dir` 유지 / 막히면: `dir = (dir + 1) % 4`

## 다음에 볼 것
- 격자 문제는 **현재 위치 + 방향 + 막히면 회전** 패턴을 먼저 익히기
- `dx`/`dy`는 반드시 **`int[]`** 로 선언
- 수학 공식은 일반 채우기 문제에선 불필요, 시뮬레이션/레이어면 충분

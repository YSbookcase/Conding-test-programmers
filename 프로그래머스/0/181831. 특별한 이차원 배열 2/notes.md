# 특별한 이차원 배열 2 (181831)

## 내가 한 질문
- 위쪽만 검사하려고 `j`를 바깥에서 관리했는데 왜 동작하지 않는가?
- `nextCh`로 수정한 방식은 맞는가?
- 다른 방법과 추가 조언은?
- 전치 후 비교는 무엇이며 더 효과적인가?
- 더 빠른 비교 방법이 있는가?

## 막혔던 지점 및 개념 정리
- **문제 본질**: 대칭 행렬(symmetric matrix) 판정. 모든 `i, j`에 대해 `arr[i, j] == arr[j, i]`이면 1, 아니면 0.
- **초기 코드 오류**:
  1. `int[,]`는 `arr[i, j]`로 접근 (`arr[i][j]`는 `int[][]`용).
  2. `arr.GetLength(1)`처럼 배열 참조 필요.
  3. `j`를 바깥에서 누적하면 첫 행 이후 `j`가 `n`을 넘어 **이후 행이 검사되지 않음**.
- **수정한 `nextCh` 방식**:
  - 매 행마다 `j` 시작을 `0, 1, 2, ...`로 올려 위쪽(대각선 포함)만 검사 → **논리적으로 맞음**.
  - 결국 `for (int j = i; j < n; j++)`와 동일.
- **전치(transpose) 후 비교**:
  - 전치: `Aᵀ[j, i] = A[i, j]` (대각선 기준 뒤집기).
  - 대칭 ⇔ 원본 == 전치.
  - 개념 설명에는 좋지만, 새 배열 복사 + 전체 비교라 **이 문제에선 더 느리고 불필요**.
- **성능**:
  - 가장 실용적인 최선은 **위쪽 삼각형만 비교 + 조기 return**.
  - 비교 횟수 약 `n(n-1)/2`. 점근적으로 더 빠른 일반 방법은 사실상 없음.
  - `n ≤ 100`이라 전체 비교도 충분하지만, 위쪽만 보는 편이 깔끔.

## 핵심 코드

### 1. 위쪽 삼각형만 비교 (최종 제출 ⭐)
```csharp
public class Solution {
    public int solution(int[,] arr) {
        int n = arr.GetLength(0);

        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) {
                if (arr[i, j] != arr[j, i]) {
                    return 0;
                }
            }
        }

        return 1;
    }
}
```

### 2. 전체 비교 (단순 버전)
```csharp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        if (arr[i, j] != arr[j, i]) return 0;
    }
}
```

### 3. 전치 후 비교 (개념용, 비추천)
```csharp
int[,] transposed = new int[n, n];
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        transposed[j, i] = arr[i, j];
    }
}
// 이후 arr과 transposed 전체 비교
```

## 방법 비교
| 방식 | 메모리 | 비교량 | 추천 |
|---|---|---|---|
| **위쪽만 비교 (최종 제출 ⭐)** | 추가 없음 | 약 n²/2 | 가장 추천 |
| 전체 비교 | 추가 없음 | 약 n² | 빠르게 짤 때 |
| 전치 후 비교 | n×n 추가 | 복사 + n² | 개념 학습용 |

## 다음에 볼 것
- `int[,]` 접근은 항상 **`arr[i, j]`**
- 대칭 판정은 **`arr[i, j] == arr[j, i]`**, 위쪽만 보면 충분
- 전치는 “대칭 = 자기 전치와 같다”는 개념용이지, 이 문제의 최적해는 아님

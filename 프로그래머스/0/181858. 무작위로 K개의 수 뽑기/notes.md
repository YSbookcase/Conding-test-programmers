# 무작위로 K개의 수 뽑기 (181858)

## 내가 한 질문
- 배열 자료형에 포함되는 함수들은 어떤 것들이 있는가? (`Contains`도 사용 가능한가?)
- `IndexOf`의 기본 개념과 동작 방식은 어떻게 되는가?
- 고정 배열로 작성한 코드에서 어떤 실수가 있었는가?
- `Array.IndexOf`에서 매개변수가 4개 들어가는 오버로딩은 어떤 의미인가?
- 고정 배열 방식 대비 `List<int>`로 풀었을 때의 장점과 `break`의 중요성은?

## 막혔던 지점 및 문법 정리
- **문법 오류**: 배열에서는 `result.IndexOf()`가 아니라 `Array.IndexOf(배열, 찾는값)` 형태의 정적 메서드로 호출해야 함.
- **기본값 0 충돌 버그**: `new int[k]`로 생성된 배열은 모든 칸이 `0`으로 채워져 있어, 실제 데이터 `0`이 처음 들어왔을 때 빈칸의 `0`과 충돌하여 중복으로 오인하고 무시되는 문제 발생.
- **`break;` 누락 위험**: `k`개를 모두 채운 이후에도 루프가 계속 돌면 `index`가 `k`를 초과하여 `IndexOutOfRangeException`이 발생하므로 조기 종료 필수.
- **남은 칸 채우기 인덱스**: `index`는 다음에 채울 위치이므로 `index + 1`이 아닌 `index`부터 채워야 함.

## 핵심 패턴 및 개념
- **`Array.Fill(배열, 값)`**:
  - 기본값 `0`과의 충돌을 방지하기 위해 배열을 문제에서 쓰이지 않는 값(예: `-1`)으로 사전 초기화할 때 매우 유용.
- **`Array.IndexOf` 4개 매개변수 오버로딩**:
  - `Array.IndexOf(배열, 찾는값, 시작인덱스, 검색개수)`
  - 전체 배열이 아닌 **실제로 채워진 유효 구간(`0`부터 `index`개)**만 한정하여 검색 가능.
- **`List<int>` vs 고정 배열 실전 감각**:
  - 중복 체크(`Contains`) 및 가변 길이 채우기(`while (list.Count < k)`)가 필요한 경우, `List`를 사용하는 것이 인덱스 관리 실수와 기본값 버그를 방지하는 가장 안전한 접근법.

## 대안별 구현 방식 정리
| 방식 | 중복 검사 | 조기 종료 | 빈자리 채우기 | 특징 |
|---|---|---|---|---|
| **List (최종 제출)** | `!list.Contains(arr[i])` | `if (list.Count == k) break;` | `while (list.Count < k) list.Add(-1);` | 직관적이고 인덱스 버그 없음 |
| **고정 배열 (`Array.Fill`)** | `Array.IndexOf(result, arr[i], 0, index) == -1` | `if (index == k) break;` | `Array.Fill(result, -1)` 사전 초기화 | 메모리 할당 1회, 인덱스 제어 필요 |

# 문자열 정수의 합 (181849)

## 내가 한 질문
- `TryParse`로 숫자로 바꾼 뒤 10으로 나누며 자릿수를 구하려 했는데 왜 실패하는가?
- `string`에서 별도의 배열 변환 없이 바로 `foreach`로 한 글자씩 순회할 수 있는가?
- 자릿수 합산 문제에서 추가로 주의해야 할 정수 자료형의 한계와 문자 변환 방식은?

## 막혔던 지점 및 개념 정리
- **정수 자료형의 자릿수 한계 (오버플로우 함정)**:
  - `int`는 최대 약 10자리(21억), `long`은 최대 약 19자리(900경)까지만 표현 가능.
  - 문제 제한사항이 **"길이 최대 100자리"**이므로 `int.Parse`나 `int.TryParse`를 시도하면 오버플로우가 발생해 파싱에 실패함.
  - 따라서 20자리 이상의 큰 수 문자열은 숫자로 한 번에 바꾸지 않고 **문자열 상태에서 한 글자씩 처리**해야 함.
- **`string`과 `foreach`**:
  - `string`은 내부적으로 `IEnumerable<char>`를 구현하므로 `ToCharArray()` 없이도 `foreach (char c in num_str)`로 바로 순회 가능 (불필요한 배열 할당 방지).

## 핵심 패턴 및 코드 발전 과정

### 1. `foreach` + 아스키 오프셋 뺄셈 (최종 제출 ⭐)
```csharp
int sum = 0;
foreach (char c in num_str)
{
    sum += c - '0'; // 문자 '5' -> 숫자 5 (아스키 53 - 48 = 5)
}
return sum;
```

### 2. LINQ 1줄 풀이
```csharp
using System.Linq;

public int solution(string num_str) {
    return num_str.Sum(c => c - '0');
}
```

## 문자(`char`) ➔ 숫자(`int`) 변환 3가지 비교
| 방식 | 코드 | 속도/성능 | 특징 |
|---|---|---|---|
| **아스키 뺄셈 (최고 ⭐)** | `c - '0'` | 🚀 **가장 빠름 (1 CPU 사이클)** | 코딩테스트 표준 테크닉 |
| **내장 메서드** | `(int)char.GetNumericValue(c)` | ⚡ 빠름 | `double`을 반환하므로 캐스팅 필요 |
| **문자열 변환 후 파싱** | `int.Parse(c.ToString())` | 🐢 **매우 느림 (비추천 ❌)** | 매 글자마다 string 힙 메모리 생성 |

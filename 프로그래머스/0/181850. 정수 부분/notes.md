# 정수 부분 (181850)

## 내가 한 질문
- 실수에서 정수 부분을 추출할 때 반올림(`Round`)이나 나눗셈을 써야 하는가?
- C#의 다양한 형변환 방식(`(int)` 캐스팅, `Parse`, `TryParse`, `Convert`)의 차이점과 사용 기준은?
- `char` 문자를 숫자로 바꿀 때의 주의점은?
- 형변환 시 `null`이 들어왔을 때 각 방식별 동작과 위험성은?

## 막혔던 지점 및 개념 정리
- **수학 함수별 동작 차이**:
  - `(int)flo` 또는 `Math.Truncate(flo)`: 소수점을 단순히 버림 (정수부만 추출 ➔ **정답**).
  - `Math.Floor(flo)`: 바닥으로 내림 (양수는 동일하지만 음수 `-1.7` ➔ `-2`로 차이 발생).
  - `Math.Round(flo)`: 반올림 처리 (`1.7` ➔ `2`가 되므로 정수부 추출 문제에서는 부적합).
- **`char` ➔ `int` 변환 시의 함정**:
  - `(int)'5'` ➔ 문자 `'5'`의 아스키코드 값인 **`53`**이 반환됨.
  - 올바른 방법: **`c - '0'`** (아스키 오프셋 빼기) 또는 `char.GetNumericValue(c)`.

## 형변환 4가지 방식 비교 및 `null` 동작

| 방식 | 주 용도 | 문자열에 사용 가능? | 숫자가 아닌 문자열("abc") 입력 시 | `null` 입력 시 | 특징 / 추천 상황 |
|---|---|:---:|---|---|---|
| **명시적 캐스팅 `(int)`** | **숫자 ➔ 숫자** (실수 ➔ 정수) | ❌ 컴파일 에러 | 컴파일 에러 | 불가 | **가장 빠름**, 소수점 버림용 (최종 제출 ⭐) |
| **`int.Parse(str)`** | **문자열 ➔ 숫자** | ⭕ | 💥 `FormatException` 예외 발생 | 💥 `ArgumentNullException` 예외 발생 | 입력이 100% 정상 숫자 문자열일 때 |
| **`int.TryParse(str, out n)`** | **문자열 ➔ 숫자** (안전) | ⭕ | 🛡️ 에러 없이 `false` 반환 | 🛡️ 에러 없이 `false` 반환 (`n=0`) | **실무/코테 입력 검증 정석** |
| **`Convert.ToInt32(val)`** | **모든 타입 ➔ 정수** | ⭕ | 💥 `FormatException` 예외 발생 | 🎁 **에러 없이 `0` 반환** | `null` 허용 데이터 처리 시 |

## `null`의 본질과 에러 발생 원리
- **`null`**: 메모리에 가리키는 대상(객체 실체)이 없는 상태.
- `int.Parse(null)`: 변환 대상 자체가 없어 `ArgumentNullException`을 던지며 프로그램이 다운됨.
- `int.TryParse(null, out n)`: 변환 실패로 안전하게 `false` 처리.
- `Convert.ToInt32(null)`: 관대하게 기본값 `0`을 반환.

## 핵심 코드
```csharp
public class Solution {
    public int solution(double flo) {
        return (int)flo; // 가장 빠르고 직관적인 정수 캐스팅
    }
}
```

## 다음에 볼 것
- 실수의 소수점 버림은 `(int)` 캐스팅 최우선 사용
- 문자열 파싱 시 안전성이 필요할 때는 `int.TryParse` 활용
- 문자(`char`) 숫자는 `c - '0'` 공식 기억

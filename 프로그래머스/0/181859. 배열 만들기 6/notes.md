- `using 네임스페이스;`를 많이 사용하면 프로그램 실행 성능에 문제가 생기는가?

## 막혔던 지점 및 문법 정리
- 배열 생성 시 변수명이 아닌 타입을 명시해야 함 (`new int[크기]`).
- `index`가 '현재 데이터 개수'이자 '다음에 들어갈 위치'일 때, **마지막 데이터의 위치는 항상 `index - 1`**임.
- 고정 배열에서 원소 삭제는 메모리를 지울 필요 없이 **`index--;`만으로 완료**됨.
- 빈 배열 검사 시 배열 내부의 값이 아닌 **`index == 0` (유효 데이터 개수)**로 판단해야 함 (데이터 `0`과의 혼동 방지).

## 핵심 패턴 및 개념
- **스택(LIFO) 시뮬레이션**: 마지막 원소와 비교 후 일치하면 제거, 불일치 시 추가.
- **타입별 배열 기본값**:
  - `int`, `long`: `0`
  - `bool`: `false`
  - `string`, 객체(참조형): `null`
- **고정 배열 vs List 성능 차이**:
  - `arr` 길이가 1,000,000처럼 대규모일 때, `List`는 2배수 재할당(Reallocation) 및 데이터 복사 비용이 발생함.
  - 고정 배열(`int[]` + `index`) 방식은 단 1회 할당 및 단순 인덱스 증감만 수행하므로 약 3~5배 빠르고 메모리 효율이 극대화됨.
- **`using` 지시문의 성능 영향**:
  - 컴파일 시점의 단축키 역할이므로 실행 시간/메모리 성능에 영향 0%.

## 대안별 구현 방식 정리
| 방식 | 마지막 원소 접근 | 추가 | 삭제 | 특징 |
|---|---|---|---|---|
| **고정 배열 (최종 제출)** | `stk[index - 1]` | `stk[index++] = arr[i]` | `index--` | 대용량 데이터에서 속도/메모리 최상 |
| **List** | `stk[stk.Count - 1]` | `stk.Add(arr[i])` | `stk.RemoveAt(stk.Count - 1)` | 코드가 직관적이고 인덱스 실수 방지 |

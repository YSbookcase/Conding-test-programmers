# 유연근무제

## 상태
- 논의·수정 후 제출 흐름 (공식 폴더 없으면 KYS24에 메모만 보관)
- 최적화 불필요 (n≤1000 × 7일)

## 내가 한 질문
- (작성 코드) 왜 틀렸지? — 주말 판정 `j == (startday+5)%7-1` 등
- 최적화 필요 없는 문제인가?
- 다른 풀이 / 개선점?
- 요일 배열을 루프 밖에 둔다는 건 변수처럼 먼저 선언하나?
- 요일 계산에 j가 들어가야 하는구나. 될 것 같은데 안 돼서 곤란했다.

## 문제 한 줄
평일(월~금)에 `희망시각+10분` 안에 출근한 직원 수. 토·일은 무시.  
시각은 `시*100+분` 정수. `startday` 1=월 … 7=일 = 이벤트 1일차 요일.

## 틀린 원인 (핵심)
```csharp
// 잘못된 예: j를 요일처럼 맞춤
j == (startday + 5) % 7 - 1 || j == (startday + 6) % 7 - 1
```
- `j`는 **이벤트 며칠째(0~6)** 이지 요일이 아님
- `% 7 - 1`은 나머지가 0이면 **-1** → 일요일 `j`를 못 잡음
- 예: `startday=5`(금)이면 토·일은 `j=1,2`인데, 위 식은 `2,3`을 스킵하고 **토요일을 평일로 검사** → `2359` 등에 지각 처리

### 올바른 요일
```text
day = (startday - 1 + j) % 7   // 0=월 … 5=토, 6=일
day == 5 || day == 6 → 주말 스킵
```
**시작 요일 + j일**이 핵심. `j`가 반드시 들어감.

## 통과 골격
```text
(선택) isWeekday[7]을 i 루프 밖에서 한 번 계산

각 직원 i:
  deadline = 희망 + 10분
  각 일 j:
    주말이면 continue
    출근 > deadline 이면 탈락 break
  평일 모두 통과면 answer++
```

## 마감시각 +10분
- 기존: `+10` 후 `% 100 >= 60`이면 `+40` (예: 855→905, 958→1008)
- 대안(가독성): 분으로 변환 후 비교
```text
ToMinutes(hhmm) = (hhmm/100)*60 + (hhmm%100)
deadline = ToMinutes(희망) + 10
지각: ToMinutes(출근) > deadline
```

## 개선 (성능 말고 정리)
- `counter==5`보다 `isPass`가 단순
- `isWeekday`를 직원 루프 **밖**에 한 번 (필수는 아님, startday 공통)
- 이름: `saveTime` → `GetDeadline` 등
- 시간 최적화는 불필요

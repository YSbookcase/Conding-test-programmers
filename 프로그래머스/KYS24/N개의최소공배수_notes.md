## 막혔던 지점
- 두 수 공식은 그대로다. `result`를 `arr[0]`으로 두고, 다음 수와 최소공배수를 구해 `result`에 다시 넣는다. 길이가 1이면 반복이 없어 그 수가 답이다.
- `Gcd`는 Greatest Common Divisor, 최대공약수다. `Lcm`은 Least Common Multiple, 최소공배수다. 함수 이름은 `Gcd`다. `GDC`는 글자 순서가 바뀐 이름이다.
- 호제법의 한 단계는 `remain = a % b`, `a = b`, `b = remain`이다. 반복은 `b != 0`인 동안이다. `while (b == 0)`이면 `Gcd(12, 8)`이 반복에 들어가지 않고 `12`를 반환한다. 최대공약수는 `4`다. `b`가 0인데 조건이 참이면 `a % b`에서 0으로 나눈다.
- 최소공배수를 구한 뒤에 다음 수를 한 번 더 곱하지 않는다. `[2, 6, 8, 14]`는 `2 → 6 → 24 → 168`이다. `168`에 `14`를 다시 곱하면 `2352`다.
- `(long)result / gcd * arr[index]` 한 줄이 두 수의 최소공배수다. `24`와 `14`의 최대공약수가 `2`이면 `(long)24 / 2 * 14 = 168`이고, 이 값이 다음 `result`다.
- `(long)`은 나눗셈 앞에 둔다. 곱이 끝난 값을 나중에 `long`으로 바꾸면 그 전에 `int`에서 넘친다. `result / gcd`는 항상 나누어 떨어진다.
- `result`를 `0`으로 시작하면 다음 계산도 `0`이다.
- 앞 수들의 최소공배수는 그 수들의 공배수 중 가장 작은 수다. 그 배수는 앞 수들로도 나누어지므로, 다음 수는 그 최소공배수와만 맞추면 된다. `[2, 6]`의 `6`으로 `2`와 `6`이 같이 맞춰지고, `6`과 `8`의 `24`, `24`와 `14`의 `168`로 이어진다.
- 소수로 보면 각 소수의 가장 높은 거듭제곱을 고르는 일이다. `2 = 2`, `6 = 2 × 3`, `8 = 2³`, `14 = 2 × 7`이라 `2³ × 3 × 7 = 168`이다. 앞에서 고른 최고 거듭제곱과 다음 수의 거듭제곱 중 더 큰 쪽을 남겨도 같다. 순서를 바꿔도 같다.

## 문제 한 줄
길이 1 이상 15 이하인 배열의 최소공배수. 원소는 100 이하의 자연수. `[2, 6, 8, 14]`는 `168`, `[1, 2, 3]`은 `6`.

## 핵심 패턴
```text
result = arr[0]
index를 1부터 끝까지
  gcd = Gcd(result, arr[index])
  result = (long)result / gcd * arr[index]
result 반환

Gcd: b != 0 인 동안 remain = a % b, a = b, b = remain. 반환은 a
```

```csharp
int result = arr[0];

for (int index = 1; index < arr.Length; index++)
{
    int gcd = Gcd(result, arr[index]);
    result = (int)((long)result / gcd * arr[index]);
}

return result;
```

- `[2, 6, 8, 14]` → `168`
- `[1, 2, 3]` → `6`
- `[7]` → `7`
- `[2, 2, 2]` → `2`

## 대안별 구현 비교

A가 연습 코드다. B는 반복 조건만 반대라 최대공약수가 달라지고, 최소공배수도 달라진다.

| 방법 | `Gcd(12, 8)` | `[2, 6, 8, 14]` |
|---|---|---|
| A. `while (b != 0)` | `4` | `168` |
| B. `while (b == 0)` | 반복 없이 `12` | `14`. 마지막 수가 남는다 |

### B. 반복 조건이 반대

```csharp
int Gcd(int a, int b)
{
    while (b == 0)
    {
        int remain = a % b;
        a = b;
        b = remain;
    }
    return a;
}
```

`b`가 `0`이 아니면 반복이 한 번도 돌지 않아 `a`가 그대로 반환된다. `[2, 6, 8, 14]`는 `Gcd(2, 6)`이 우연히 `2`라 첫 결과는 `6`이 되지만, `Gcd(6, 8)`은 `2`가 아니라 `6`이다. `6 / 6 * 8 = 8`, `8 / 8 * 14 = 14`가 되어 마지막 수가 답처럼 남는다. `b`가 `0`으로 들어오면 `a % b`에서 0으로 나눈다.

최소공배수를 만든 뒤 다음 수를 한 번 더 곱하면 A의 `168`이 `2352`가 된다. `(long)`을 곱셈 뒤에 두면, 답이 `int`에 들어가는 경우에도 중간 곱에서 깨질 수 있다.

## 내가 한 질문
- 등차수열 합으로 구했는데 `long`이라 변수를 먼저 선언했다. `(long)`으로 하려니 더하고 곱해야 하는데 `((long)a + b)`가 안 됐다.
- `long` 변수를 먼저 두는 편이 안전하지 않나. 처음에 메모리를 잡더라도.
- 추가로 볼 점이 있나?
- `1L * 개수 * (a + b) >> 1`은 뭔가. 나눗셈을 이상하게 하는 것 같다.
- 음수 홀수일 때는 문제가 되는구나.
- 시프트하면 왜 값이 달라지나. 음수 표기 때문인가. 왜 홀수만?
- 음수는 내부에서 양수 표기를 뒤집어 표현하는 건가?

## 막혔던 지점
- 반환은 `long`이다. `1`부터 `10000000`까지 합은 `50000005000000`이라 `int`에 안 들어간다.
- `(long)`은 바로 뒤의 한 덩어리만 바꾼다. `(long)a + b * 개수`는 곱셈이 먼저라 `b * 개수`가 `int`로 계산된다.
- `((long)a + b) * 개수 / 2`는 덧셈이 `long`이고, 그 결과에 `int`를 곱하므로 곱셈도 `long`이다.
- `(long)((a + b) * 개수 / 2)`는 이미 넘친 `int`를 바꾼다. `1`, `10000000`에서 `143223616`이 나온다.
- `long x = a`, `long y = b`로 먼저 올리면 뒤의 덧셈과 곱셈이 전부 `long`이다. 힙에 배열을 잡는 것은 아니다. `long` 지역 변수는 8바이트이고, `(long)a`도 계산 중에 같은 크기의 값을 만든다.
- 나눗셈은 곱한 뒤에 한다. `(y + x) / 2 * 개수`는 `1`, `2`에서 `(1 + 2) / 2`가 `1`이 되어 합이 `2`가 된다. 정답은 `3`이다. 양 끝의 합과 개수를 먼저 곱하면 항상 짝수라 `/ 2`가 떨어진다.
- `a`가 `b`보다 커도 `Math.Abs(y - x) + 1`이 개수다. `5`, `3`은 `12`다.
- `>> 1`은 비트를 오른쪽으로 한 칸 미는 연산이다. `*`가 `>>`보다 먼저라 `1L * 개수 * (a + b) >> 1`은 곱한 뒤 한 칸 민다. `1L`은 `long` 1이라 곱셈을 `long`으로 올린다. `3`, `5`는 `24`를 밀어 `12`다.
- 음수 홀수에서 `/`와 `>>`가 갈린다. `-5 / 2`는 `0` 쪽으로 버려 `-2`다. `-5 >> 1`은 더 작은 쪽으로 내려 `-3`이다. 짝수는 나머지가 없어서 같다. `-6 / 2`와 `-6 >> 1`은 둘 다 `-3`이다.
- 이 공식의 `개수 * (a + b)`는 항상 짝수다. `-2`, `-1`이면 곱이 `-6`이라 `>> 1`과 `/ 2`가 둘 다 `-3`이다. 양 끝의 합이 음수 홀수일 때 그 합을 먼저 `>> 1` 하면 `(-3) >> 1`이 `-2`가 되어 실제 합 `-3`과 어긋난다.
- 음수는 비트를 뒤집고 1을 더한 값이다. `5`를 8비트로 쓰면 `00000101`, 뒤집으면 `11111010`, 1을 더하면 `11111011`이다. 이 비트가 `-5`다. 둘을 더하면 앞자리가 잘리고 8비트는 `00000000`이 된다.

## 문제 한 줄
`a`와 `b` 사이에 있는 모든 정수의 합을 `long`으로 반환한다. 순서는 정해져 있지 않고, 같으면 그 수를 반환한다.

## 핵심 패턴
```text
long x = a
long y = b
return (x + y) * (Abs(x - y) + 1) / 2
```
- `3`, `5` → `12`
- `3`, `3` → `3`
- `5`, `3` → `12`
- `1`, `10000000` → `50000005000000`

## 대안별 구현 비교

예제 세 개는 같다. `1`과 `10000000`에서 캐스트가 늦은 식만 `143223616`이 된다. `1`과 `2`에서는 나누기를 먼저 하면 `2`가 되고 정답은 `3`이다. `>> 1`은 곱이 짝수인 이 공식에서 `/ 2`와 같다.

### A. `long`으로 올린 뒤 공식
LocalTest에 둔 버전. 뒤 계산이 전부 `long`이다.

```csharp
using System;

public class Solution {
    public long solution(int a, int b) {
        long x = a;
        long y = b;
        return (y + x) * (Math.Abs(y - x) + 1) / 2;
    }
}
```

### B. 덧셈만 먼저 `long`
결과는 A와 같다. 괄호 밖으로 곱셈이 나가면 `int`로 넘친다.

```csharp
using System;

public class Solution {
    public long solution(int a, int b) {
        return ((long)a + b) * (Math.Abs(a - b) + 1) / 2;
    }
}
```

### C. `1L`과 `>> 1`
곱한 뒤 한 칸 민다. 이 공식에서는 A와 같은 값이다.

```csharp
using System;

public class Solution {
    public long solution(int a, int b) {
        return 1L * (Math.Abs(a - b) + 1) * (a + b) >> 1;
    }
}
```

### D. 캐스트가 늦거나 나눗셈이 먼저
`1`, `10000000`에서 앞 식은 `143223616`이다. `1`, `2`에서 뒤 식은 `2`다.

```csharp
long late = (long)((a + b) * (Math.Abs(a - b) + 1) / 2);
long divideFirst = ((long)a + b) / 2 * (Math.Abs(a - b) + 1);
```

## 다음에 볼 것
- `(long)`은 바로 뒤만 바꾼다. 합을 `long`으로 쓰려면 덧셈을 괄호로 묶거나 변수를 먼저 `long`으로 둔다.
- `/ 2`는 곱한 뒤에 한다.
- `>> 1`은 양수와 짝수 음수에서 `/ 2`와 같다. 음수 홀수는 `-5 >> 1`이 `-3`, `-5 / 2`가 `-2`다.
- 음수 비트는 뒤집고 1을 더한 값이다.

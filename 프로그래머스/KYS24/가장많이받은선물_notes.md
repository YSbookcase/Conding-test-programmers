# 가장 많이 받은 선물

## 상태
- 학습용: `프로그래머스/KYS24/가장많이받은선물_학습.cs`
- 공식 폴더가 생기면 그 `notes.md`로 이동

## 내가 한 질문
- 관계표·선물지수 구한 뒤 비교가 맞아 보인다. `Length - i`로 관계, 카운터 최댓값 갱신. 2차원 give + 1차원 지수. Split 메서드 이름이?
- Dictionary 활용·`give`의 a,b가 뭔지 모르겠다 → 코드 작성 부탁
- 자료구조 구성이 머리로 안 잡힘. `j = i+1`로 주고받음을 한 번에 보는 디테일을 놓칠 것 같다
- (마무리) 성능 문제 없나?
- (별도) 경로 탐색 부트캠프에서 본 것 — 반복 익숙해져야 하나? → 별 주제, BFS 우선

## 문제 한 줄
친구 쌍마다 다음 달 선물 규칙을 적용해, **가장 많이 받는 사람의 개수**를 구한다.

## 규칙 요약
1. 둘 사이 준 횟수가 다르면 → 더 많이 준 쪽이 하나 받음
2. 같거나 기록 없음 → 선물지수(준−받은) 큰 쪽이 받음
3. 지수도 같으면 → 없음

## 자료구조
| 구조 | 의미 |
|------|------|
| `Dictionary<string,int>` | 이름 → 인덱스 |
| `give[a,b]` | a가 b에게 준 횟수 |
| `score[i]` | 준 합 − 받은 합 |
| `next[i]` | 다음 달 받을 개수 |

```csharp
gift.Split(' ');  // [0]=준 사람, [1]=받은 사람
give[giver, receiver]++;
```

## `j = i + 1` 의미
무순서 쌍 `(i,j)`를 **한 번만** 본다.  
한 번의 비교로 `give[i,j]` vs `give[j,i]`를 보고 승자 `next++`.  
`(j,i)`를 또 돌면 중복.

## 성능
- n ≤ 50, gifts ≤ 10,000
- gifts 처리 O(gifts), 쌍 비교 O(n²) ≈ 2,500
- **최적화 불필요**, 현재 구조로 충분

## 학습 메모
- “표를 문제로 주면 → 2차원 배열로 옮긴다”
- 이름 키면 Dictionary로 인덱스화
- 쌍 비교는 `i < j` 패턴
